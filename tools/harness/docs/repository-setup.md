# 레포 단위 설치 구성안

작성일: 2026-10-30 / 단계: 초기 범위 정리 + 구현 상태 갱신

초기 제안 중 현재 구현된 구성과 명령은 [도구 안내](tools.md)와 [구조](architecture.md)를 따른다.
아래의 추가 도구·프레임워크 제안은 채택된 기본값이 아니다.

이 레포와 정해진 설치 절차로 다른 노트북에서도 하네스를 구성한다.
지침·스킬·도구 연결·실행 방법은 레포에서 관리하고, 현재 컴퓨터의 개인 설정이나 플러그인을 필수 입력으로 삼지 않는다.
아래 목록은 현재 코드가 요구하는 항목과 새로 구성할 제안을 구분한다. 구체적인 도구 선택을 모두 확정한 상태는 아니다.

## 현재 요구와 확인한 상태

| 항목 | 현재 상태와 근거 |
| --- | --- |
| 라우터와 실행 | [Python 코드](../harness/routing/cli.py)에 catalog/route와 run/chat이 있다. [실행·훅 인수인계·현재 한계](execution.md)를 따른다. |
| Python | 표준 TOML 파서 `tomllib`를 사용하므로 현재 코드는 Python 3.11 이상이 필요하다. 외부 Python 패키지를 가져오는 코드는 없다. |
| Codex CLI | 모델 목록 조회와 선택적인 분류 호출에 사용한다. 목록 파일을 제공하는 규칙 전용 실행은 CLI 없이도 가능하다. |
| 프로젝트 구성 | 루트 `AGENTS.md`, Codex 공식 HTTP MCP 설정 2개, 공통 스킬 7개, setup/doctor/check/task 도구가 있다. 브라우저는 선택 설치다. |
| 기존 점검 | 자동 테스트 파일은 있다. 이번 단계에서는 모듈 도움말이 실행되는 것을 확인했다. |
| 현재 관측 버전 | Python 3.14.7, Codex CLI 0.166.0. 지원 버전으로 고정한 값은 아니다. |
| 이전 기록과 차이 | [10월 22일 기록](cli-capabilities.md)은 Codex 0.163.0 기준이다. 현재 도움말에 목록 조회와 분류용 주요 옵션이 남아 있음을 확인했다. 실제 모델 호출과 전체 호환성은 미확인이다. |

## 실행 도구 구성안

| 항목 | 구분 | 레포에서 준비할 것 | 설치 후 점검할 것 |
| --- | --- | --- | --- |
| Git | 레포를 받기 위한 준비 도구 | 필요한 설치 안내와 레포 기준 경로 처리 | 다른 경로에 받은 레포에서도 시작 가능한지 |
| Python | 현재 라우터의 실행 도구 | 지원 버전 정보와 프로젝트 실행 환경 | 모듈 도움말, 정책 읽기, 자동 테스트 |
| Codex CLI | 현재 라우터 사용 시 필요 | 검증한 버전과 설치·실행 경로 | 요구 옵션, 목록 형식, 로그인, 실제 호출을 각각 구분해 확인 |
| Node.js 등 추가 런타임 | 설치 방식이나 선택 MCP가 요구할 때 추가 | 선택한 패키지의 요구 버전과 잠금 정보 | 실행에 실제로 필요한지, 버전이 맞는지 |

실행 도구는 Codex 공식 클라이언트를 사용한다. 현재 라우터는 Codex 모델만 추천한다.
작업용 모델·추론 기본값이나 분류용 모델을 이 설치 단계에서 새로 지정하지 않는다.

## MCP와 기본 도구 구성안

| 기능 | 초기 제안 | 이유와 적용 조건 |
| --- | --- | --- |
| 파일 읽기·편집·셸·로컬 Git | 클라이언트 기본 도구 사용 | 같은 기능의 MCP를 중복으로 요구하지 않는다. |
| OpenAI 공식 문서 검색·읽기 | 첫 문서 MCP 후보 | 하네스와 Codex 설정을 개발할 때 사용. 공개 HTTP 서버여서 로컬 MCP 서버 패키지가 필요하지 않다. |
| 일반 라이브러리 문서 조사 | 추가 문서 MCP 선택 검토 | 조사 대상이 늘 때 필요한 범위와 인증 조건을 확인해 선택한다. |
| 일반 웹 검색·원문 확인 | 연구 작업에 필요한 능력으로 포함 | 클라이언트 기본 도구로 충족되는지 확인하고, 부족한 경우 연결 도구를 선택한다. 문서 MCP를 범용 검색으로 취급하지 않는다. |
| 브라우저 조작·화면 검증 | UI 작업용 선택 기능 | 브라우저 도구와 설치할 브라우저를 함께 정한다. |
| GitHub 등 외부 서비스 | 해당 작업에 필요한 선택 기능 | 기본 도구·CLI·MCP 중 필요한 방법을 선택하고 인증은 노트북에서 수행한다. |
| 작업 기록·인수인계 | 우선 프로젝트 파일 기반 구성 검토 | 개인 컴퓨터의 과거 세션과 기억만으로 필수 맥락을 대신하지 않는다. 저장·검색 방식은 후속 설계다. |

현재 라우터의 분류 프로세스는 MCP와 여러 도구를 끄도록 구성돼 있다.
연구·구현을 수행할 작업용 도구 연결과, 작업 특성만 판단할 분류기의 도구 구성을 구분한다.
MCP 설정을 만들었다는 사실만으로 현재 분류기에 그 도구가 제공되는 것은 아니다.

## 레포에서 제공할 지침과 스킬

| 구성 | 역할 | 이후 만들거나 연결할 위치 |
| --- | --- | --- |
| 공통 지침 | 목적, 구조, 실행·검증 명령, 작업 경계, 완료 보고 | 루트 `AGENTS.md`. |
| Codex 프로젝트 설정 | 필요한 MCP와 지원되는 실행 설정 | `.codex/config.toml` |
| 연구 스킬 | 질문 분해, 탐색, 근거 확인, 종합, 불확실성 전달 | Codex `.agents/skills/`의 프로젝트 스킬 |
| 설계 스킬 | 요구와 제약 정리, 대안 비교, 실패 상황·인터페이스 검토 | 같은 프로젝트 스킬 구성 |
| 구현 스킬 | 기존 동작 확인, 변경, 필요한 테스트·실행 검증 | 같은 프로젝트 스킬 구성 |
| 검증과 리뷰 스킬 | 완료 기준 대조, 오류·반례 탐색, 보완·재확인 | 같은 프로젝트 스킬 구성 |

스킬은 `.agents/skills/` 한 곳에서 관리하고 Codex가 직접 읽는다. 별도 동기화나 사본을 만들지 않는다.
기존 [공통 작업 규격](task-workflow.md)은 스킬을 설계할 때 참조하되, 이번 구성 목록을 승인된 자동 실행 절차로 간주하지 않는다.
Superpowers·ECC·OMX 같은 전체 프레임워크의 채택 여부는 아직 정하지 않았다.

## 설치와 점검에 포함할 범위

설치 흐름은 레포 받기 → 실행 환경 준비 → 프로젝트 구성 설치 → 필요한 인증 → 점검 → 사용으로 잡는다.
설치·점검·시작 진입점을 제공하되, 구체적인 명령 이름과 구현 언어는 후속 단계에서 정한다.

- 실행 도구와 선택 패키지는 검증한 버전·출처를 기록해 설치한다. 관측한 최신 버전을 곧바로 호환 버전으로 선언하지 않는다.
- 프로젝트 의존성과 설치 산출물은 레포별로 관리하는 방안을 우선 검토한다. 운영체제·클라이언트 제약 때문에 사용자 영역에 필요한 설치와 인증은 구분해 안내한다.
- 설치 과정에서 개인 설정 파일을 복사하거나 덮어쓰지 않는다. 개인 플러그인과 미등록 전역 명령을 필수 의존성으로 숨기지 않는다.
- 경로는 레포 기준으로 계산한다. 현재 사용자명, 홈 디렉터리, Homebrew 경로를 실행 조건으로 고정하지 않는다.
- 반복 설치 시 같은 구성을 재현하고 기존 개인 값을 보존할 수 있도록 한다.
- 점검은 실행 파일 존재, 버전, 지침·스킬 로딩, MCP 연결, 인증, 실제 작업 호출을 각각 구분한다.
- 모델을 호출하지 않는 기본 점검과 실제 모델을 사용하는 점검을 분리해 사용량 발생 여부를 표시한다.

## 공유할 파일과 노트북별 상태

레포에는 지침·프로젝트 설정·스킬 원본·설치 정보·점검 도구·환경 변수 예시·테스트를 둔다.
비밀값·인증 자료·다운로드한 실행 파일·가상환경·캐시·개인 실행 기록은 공유 대상에서 제외한다.
설치기는 이 구분에 맞는 저장 경로와 Git 제외 설정도 함께 마련해야 한다.

프로젝트 설정은 사용자·관리 설정과 함께 적용될 수 있다. 설치 파일만 레포에 넣었다고 실행 환경이 완전히 격리되는 것은 아니다.
개인 전역 설정과 플러그인 없이도 필요한 구성이 로딩되는지 별도 환경에서 확인하고, 외부 정책 때문에 달라지는 부분을 기록한다.
현재 SSH 서버 읽기 전용 등 작업 경계는 설치로 완화하지 않는다.

## 다음 단계와 미결정 사항

기본 지침·프로젝트 설정·스킬·설치·점검·검증 도구를 연결했다. 다음에는 실제 프로젝트 주제를 받고 작은 기능에 적용해 평가한다.

지원 운영체제, 실행 도구의 구체적인 설치 위치와 고정 버전, 추가 MCP·프레임워크 선택은 미결정이다.
현재 macOS에서 확인한 버전·도움말만으로 다른 운영체제나 새 노트북에서의 설치 성공을 주장하지 않는다.

## 구성 위치를 확인한 공식 문서

- [Codex 프로젝트 설정](https://learn.chatgpt.com/docs/config-file/config-basic): 레포의 `.codex/config.toml`과 프로젝트 신뢰.
- [Codex 설정 제약](https://learn.chatgpt.com/docs/config-file/config-advanced): 프로젝트 설정에서 지원하지 않는 키와 사용자·관리 설정의 관계.
- [Codex 프로젝트 스킬](https://learn.chatgpt.com/docs/build-skills): `.agents/skills/`의 탐색과 스킬 구성.
- [OpenAI Docs MCP](https://developers.openai.com/learn/docs-mcp): 공개 문서 검색·읽기 서버와 제공 범위.
