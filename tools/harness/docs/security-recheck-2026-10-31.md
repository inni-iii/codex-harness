# 보안 하네스 재점검 — 2026-10-31

대상은 이 레포의 로컬 보안 절차·검사 실행기·병렬 검증·완료 근거다.
보안 작업의 계획·구현 검토·안전한 재현·수정 후 회귀 검증을 돕는 기반으로 사용한다.
제품의 취약점 부재·악성 코드의 안전한 실행·모델 판단의 정확성을 자동 인증하지 않는다.
검토와 수정은 같은 에이전트가 수행했다. 독립 보안 감사로 표현하지 않는다.

## 요구와 점검 범위

사용자 결정 원문은 접근 가능한 Claude/Codex 전체 기록에서 관련 항목을 검색해 확인했다.
원문 UTC 2026-10-30의 결정은 보안 진입점 한 개, GitHub/CI 없이 로컬 설계·구현·공격 사례 검증, 전역 스킬 없는 재현이다.
이후 병렬 작업 요구에 따라 일반 구현·로컬 검사는 계속하고 관련 보안 미결이 있는 범위의 완료만 보류한다.
Claude의 관련 검색에서 이번 하네스 결정에 해당하는 사용자 원문은 추가로 확인되지 않았고 plans 경로는 없었다.
접근 가능한 기록 검색과 관련 원문 확인을 모든 과거 대화의 정독으로 표현하지 않는다.

## 재현하고 보완한 결함

1. **경로 표기 차이로 보안 범위가 빠짐.** `backend/other/../auth/session.py`가 실제 인증 파일인데 인증 pending/필수 테스트가 선택되지 않았다. 검사 전 경로와 선택한 workflow 경로를 정규화했다. 같은 파일의 ./·중복 슬래시·내부 ../ 표기로 pending과 required를 각각 검증한다.
2. **모순된 JUnit 집계가 통과함.** errors=-1과 failures=1이 상쇄되거나 실제보다 많은 tests, 실제 태그와 다른 skipped 선언이 통과했다. 음수/비정수와 tests/skipped 불일치를 거부하고 실제 failure 태그·suite 오류를 유지한다.
3. **행동 검사가 아닌 결과로 구현을 닫음.** 다른 행동 검사가 함께 통과한 보고서에서 covers_behavior=false인 검사 ID를 완료 근거로 지정할 수 있었다. 결과에 검사 성격을 기록하고 완료 시 해당 검사 ID가 행동 검사인지 검증한다.
4. **실행 권한 변경 후 옛 통과를 재사용함.** 실행 파일의 execute 권한을 제거해도 내용 해시가 같아 캐시 통과가 재사용됐다. 캐시 지문·현재 완료 근거·사본·실험 비교에 실행 권한을 포함했다. 파일 경계도 길이로 구분해 지문 입력을 명확히 했다.
5. **의존성 검사 프로세스 정리의 권한 오류 처리 부족.** 그룹 종료가 거부되면 예외가 빠져나가 루트 프로세스 종료가 생략될 수 있었다. 공통 정리 절차로 루트 종료를 시도하고 원래 실패와 cleanup_error를 구분한다. 자손 전체 종료를 보증하지는 않는다.
6. **엄격한 JSON 처리의 빈틈.** 1e999가 Infinity로 변환돼도 허용됐고 중첩 제한이 인터프리터에 의존했다. 유한 실수와 최대 64단계 컨테이너 깊이를 검사하고 parser recursion 오류도 제한된 ValueError로 바꾼다.
7. **감사 대상 해시와 실제 복사본의 경합.** npm lock을 해시용과 복사용으로 따로 읽었다. 중간 변경 후 원복되면 다른 복사본을 조회하고 옛 입력의 성공처럼 남길 수 있었다. 실제 검증·전달한 lock 바이트를 해시하고 원본과 대조한다.

추가로 Python 버전이 같아도 실행 환경이 다르면 현재 근거를 차용하지 못하도록 실행 파일과 환경 prefix를 기록한다.
관련 테스트는 일반 정상 사례와 함께 실행한다. 취약한 상태의 거짓 통과 재현과 수정 후 거부를 구분하며 실제 서비스나 외부 시스템을 공격하지 않는다.

## 후속 반복 점검과 수렴 조건

사용자의 추가 요청에 따라 이전 회귀의 재확인 → 새로운 우회/경합 가설 → 반례 실행 → 보완 → 새 경계의 재확인으로 이어갔다.
통과 횟수를 늘리는 대신 실제로 판정을 깨뜨리는 입력과 상태 변화를 먼저 찾았다.

| 추가 점검에서 확인한 경계 | 보완과 확인 |

추가 회귀는 test_security_profiles.py, test_security_final_boundaries.py, test_parallel_checks.py, test_workflows.py에 있다.
일부 경계 검사는 안전한 가짜 실행기·보고서를 사용한다. 실제 제품 권한 검증으로 확대하지 않는다.
동시에 진행된 검증 작업의 캐시 원본 재판정·완료 중 task/review 변경·실험 원본 연결 보완도 보존하고 최종 결합 상태에서 검사한다.
후속으로 추가된 .codex/hooks.json·보안 도구 manifest·docs/knowledge/catalog.json도 실행/규칙 변경에 대한 Python 회귀 선택 경로에 연결했다. hook의 실제 클라이언트 활성화·신뢰 승인까지 이 검사로 인증하지 않는다.
후속 기록은 docs/tasks/security-convergence-review의 finding ID와 review 라운드에 연결한다. 수정 전 코드는 .runtime/security-convergence-proofs의 격리 사본으로 보존하고 현재 제어기로 실제 unittest 실패 보고서를 수집한다. 공유 원본을 과거 코드로 되돌리지 않는다.
메타데이터 hook은 task 상태를 정해진 문자열로 제한해 상태 필드에 넣은 임의 객체/본문을 checkpoint에 복사하지 않는다. 정상 checkpoint와 잘못된 상태의 무기록 거부를 확인한다.

이번 점검의 종료 조건은 다음과 같다.

1. 확인한 거짓 통과·누락·경합 재현이 보완 뒤 거부되고 정상 대조군은 동작한다.
2. 관련 회귀와 최종 고정 사본의 전체 등록 검사가 통과하며 실패·skip·환경 미확인을 구분한다.
3. 수정 뒤 입력 경계와 근거 연결을 다시 읽고 새로 재현되는 미해결 결함이 남지 않는다.
4. 외부 조회 실패·OS 정리 권한·실제 서비스/모델 미검증을 안전성 보증으로 바꾸지 않는다.

이는 검토한 위협 모델과 지원 계약에서의 자신감이다. 임의의 미래 취약점 부재나 같은 OS 계정의 악성 프로세스로부터의 보호를 증명하는 조건은 아니다.

## 재현 명령과 결과 해석

레포 루트에서 프로젝트의 정상 Python 인터프리터로 실행한다.

```sh
python3 tools/harness/run.py doctor
python3 tools/harness/run.py check --snapshot --full --checkpoint final
python3 tools/harness/run.py context --kind review --paths tools/harness/harness/security.py tools/harness/harness/security_profiles.py --topic security --read
```

검사 결과와 각 테스트 수·실패·skip·현재 원본 변경 여부는 명령이 반환한 report.json과 원본 로그에서 확인한다.
사본 통과를 현재 원본의 통과로 쓰려면 소스·실행 권한·실행 환경을 다시 대조한다.

실제 npm 감사도 공개 browser/package-lock.json을 대상으로 설치 없이 실행했다.
npm 11.19.1이 registry 조회의 ENOTFOUND를 반환해 결과는 incomplete다. 알려진 취약점 0개라고 보고하지 않는다.
고정 응답 대역 테스트는 감사 실행기 계약의 근거이며 실제 advisory 조회 성공을 대신하지 않는다.
실제 서비스가 없으므로 제품 인증·권한/API/DB·브라우저 E2E·실제 모델의 prompt injection 내성은 이번에 검증하지 않았다.

## 신뢰 범위와 남은 제한

- 스킬은 에이전트의 판단 절차다. 항상 읽히거나 모든 지침이 준수됨을 강제하는 실행 차단기가 아니다.
- 보호 조건과 테스트가 실제 요구를 검증하는지 코드를 읽고 리뷰해야 한다. 올바른 해시·형식·테스트 개수만으로 의미상 보안을 증명하지 못한다.
- 등록 명령과 로컬 실행 파일은 사전에 검토한 입력을 전제로 한다. 임의의 악성 저장소나 테스트를 안전하게 실행하는 OS sandbox가 아니다.
- 고정 사본은 파일 입력을 고정한다. 상속 환경변수·외부 네트워크·DB·포트·브라우저 상태까지 격리하지 않는다. 실제 비밀값과 운영 데이터를 넣지 않는다.
- 패턴 검사는 제한된 텍스트 규칙이며 기본 범위에서 무시된 로컬 파일·Git 이력은 제외한다. advisory 조회는 악성 패키지·미공개 취약점을 찾아주는 도구가 아니다.
- 내장 패턴 검사는 파일당 2 MiB·전체 64 MiB의 UTF-8 텍스트가 지원 범위다. 바이너리·지원하지 않는 인코딩·상한 초과는 incomplete이며 제품 자산이 생기면 적합한 검사 도구/범위를 연결해야 한다. 이를 무검사 통과로 바꾸지 않는다.
- 그룹 신호가 차단되는 실행 환경에서는 루트 종료를 시도해도 자손 전체 정리가 보장되지 않는다. 해당 제한을 숨기고 통과로 만들지 않는다.
- 설치한 모든 패키지·인터프리터 바이너리·DB·외부 상태의 무결성을 추적하는 시스템은 아니다. 외부 상태에 의존하는 검사는 캐시하지 않고 실제 환경에서 검증한다.
- 검토 대기는 독립 작업의 구현을 막지 않는다. 영향 범위를 모르거나 공유 계약에 의존하면 그 부분의 완료는 계속 미확인으로 남긴다.

이 한계 안에서 반복 가능한 로컬 보안 작업을 맡기는 기반으로 사용한다. 서비스가 생기면 실제 사용자·자원·역할과 정상/거부/경합 사례를 등록해야 그 서비스에 대한 판단이 가능하다.
