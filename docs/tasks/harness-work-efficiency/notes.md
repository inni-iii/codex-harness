# 작업 기록

중요한 발견·실패·정정과 그 근거를 날짜와 함께 기록한다.
공통 규칙으로 만들 후보는 적용 조건·제외 조건·재현/회귀 근거를 함께 남긴다.

## 검증 계획

- 사용자 결과 기준의 의미 있는 작업 묶음:
- 이번 검증 범위·checkpoint와 사용자에게 알린 내용:
- E2E 수행 여부·시점·사유와 미룬 검사:
- 격리 위치·기준 상태·통합 시 함께 유지할 요구:

## 확인한 결함과 회귀

실제 결함을 확인하면 ID·증상·재현 입력·기대 결과·근거를 즉시 적는다. 추측과 환경 오류는 구분한다.
수정 전 실패·수정 후 통과·테스트/시나리오 위치·검사 수집 조건·미실행 이유를 보존한다.
마지막 수정 뒤의 재검토를 남기고 review.json의 verification.findings/rounds에 연결한다.

## 인수인계

- 목표·범위·현재 상태와 이어서 읽을 자료:
- 확정 결정·이유·미결정:
- 수용 기준별 실제 명령·cwd·대상 상태·결과·근거 위치:
- 실패/탈락한 방법·당시 조건·재검토 조건:
- 남은 문제·환경 전제:
- 다음 한 행동(파일/함수/명령과 관측할 결과):

다른 노트북에 없는 로컬 로그는 재현 명령도 남긴다. 비밀값·개인 경로는 기록하지 않는다.

## F1: 단계 시간의 낙관적 충돌 토큰

2026-11-04 새 timing mark를 검토하다 ledger를 읽은 뒤 충돌 토큰을 계산해, 그 사이 다른 작성자가 갱신하면 최신 해시와 옛 데이터를 결합할 수 있음을 확인했다. state 반환 직후 외부 갱신을 넣는 자동 회귀로 재현하고, 읽기 전 토큰을 반환하도록 보완한다. 요구/범위 변경이 아닌 이번 구현 결함이다.

## F2: 새 관측 CLI의 성공 종료 코드

2026-11-04 실제 timing report에서 JSON은 observed지만 공통 CLI의 성공 상태 목록에 새 상태가 없어 종료2가 발생했다. inspect·mark·반복 mark·report의 실제 CLI 종료 코드를 자동 검사하고 새 명령에 한해 성공 상태를 연결한다. F1 회귀와 함께 수정 전 보고서를 보존한다.

## 최종 통합과 검토

- cwd는 레포 루트. 격리 관련 신규12개·기존 evidence12개/integrity9개 통과. 좁은 RED는12개/실패2, 수정 뒤 같은 파일12개/실패0. 전체 등록 검사는 통합 후 한 번: 520개/실패0/skip1, 종료0.
- 최종 보고서: .runtime/check-snapshots/c73766bbeb9b4273aa98fb22b435602c/checks/deb5fbc392b1471bbf7a256ab568c76e/report.json. 실행 시간 합계84.975초; 실제 명령/환경/로그·사본 상태는 보고서에 보존.
- 기존 skip은 sandbox의 프로세스 그룹 신호 제한 하위 사례다. 신규12개는 모두 실행됐다. E2E는 앱/UI 변경이 없어 비적용.
- baseline 해시로 범위19파일만 통합했고, AGENTS의 타 세션 프로젝트 설명 행을 보존한 상태로 우리 재사용 규칙만 병합했다. catalog/발견 F1/F2의 현재 상태에 명시 restart하고 v2의 동일한 설계/정렬을 유지했다.
- StaticCheck flow_catalog는 다른 세션의 project-explanation 등록 중간 상태였고 현재 doctor가 재현하지 않는다. hook status는 최신 passed와 pending_failures=[]로 확인했다. 타 세션 소스는 임의 수정하지 않았다.
- evidence import/inspect/review-template의 실제 공용 명령을 사용했다. 리뷰의 실행 사실/계약 해시는 도구가 만들고 기준별 이유·F1/F2 판정은 현재 에이전트가 자체 작성했다. 자동 승인·독립 평가로 주장하지 않는다.
- timing은 mark 이전을 unclassified로 남겼고 실행 시간과 단계 경과의 중첩/재사용을 명시한다. 성능 개선율은 아직 미측정이다.

## 외부 문서 변경 후 근거 갱신

최종 사본520개 검사는 통과했으나 그 뒤 다른 세션이 docs/projects를 삭제해 문서 링크 정리 작업 removed-project-links를 시작했다. 해당 세션이 현재 지도 링크를 수정해 doctor가 다시 통과했다. 삭제를 되돌리거나 타 세션 작업을 임의 수정하지 않았다. 이전 GREEN/리뷰는 runtime 원본/백업과 GREEN_PRIOR artifact로 보존하고 현재 완료 근거로 쓰지 않는다. 현재 코드 변경 없이 새 결합 상태의 전체 검증을 한 번 더 실행하는 이유는 이 소스 변경이며, 무조건 반복하는 기본 절차로 만들지 않는다.
