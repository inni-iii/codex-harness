# 반복 작업 비용 보완 결과

2026-11-04 승인 범위에 따라 기존 운영 지침과 공용 기록 도구를 보완했다. 자동 통과 판단·원격 쓰기·개인 로그 수집·새 패키지/스킬은 추가하지 않았다.

## 운영 방식

- 동일 대화에서 읽은 원문·명령·유효한 근거를 재사용하며, 전체 과거 기록 검색 범위를 유지해 새 기록/주제/변경분을 추가 확인한다. 필요한 절·이번 diff·실패 구간을 읽고 큰 출력을 반복하지 않는다.
- 질문별 적용 조건·대안/반례·불확실성이 채워지면 조사를 종료한다. 출처 수를 목표로 수집하지 않는다.
- 격리 공간은 관련 검사/실제 사례를 먼저 실행하고 통합 후 필요한 전체 검사를 수행한다. 중간 전체 검사는 공유 위험·새 변화·실패/불확실성 등의 이유가 있을 때 실행한다.
- 결과 본문은 정본에 두고 작업/리뷰는 근거 ID와 기준별 판단을 연결한다.

## 실제 명령

레포 루트에서 `evidence import <task> --manifest <상대 JSON>`은 여러 ID와 여러 수용 기준을 기존 method에 연결한다. 모든 행이 성공해야 한 번 task를 저장하며 실패 시 기존 작업/리뷰를 보존한다. `evidence inspect <task>`와 `review-template <task> --output <새 상대 JSON>`은 실행 사실·기준 참조를 준비하고 reviewer/판정은 비워 둔다. 기존 review.json을 덮어쓰지 않는다. verify/complete는 현재 소스/환경과 실제 근거를 계속 대조한다.

`timing mark <task> <phase>`·`timing report <task>`는 명시한 단계의 경과를 기록한다. mark 이전은 unclassified이며 자료가 없는 과거 활동 시간을 만들지 않는다. 등록된 check 보고서의 실행 시간은 별도 합계이고 단계 시간과 겹친다. 재사용된 검사 시간은 원래 실행의 값이다.

## 실행과 반례

- 신규 자동 검사12개: 묶음 정상/부분 실패·중복·잘못된 경로/기준·source 날짜·method·symlink·다른 작성자의 task 변경, 리뷰 보존/통과 차단·실행 사실/변조/오래된 소스, 단계 집계/완료 시각/시계 역행/중복 참조 및 CLI 종료 코드.
- 기존 evidence12개·verification_integrity9개도 통과했다. 통합 후 현재 전체 등록 결과는 task evidence에 연결한다.
- F1: ledger를 읽은 뒤 토큰을 계산하면 읽기 직후의 외부 갱신을 덮을 수 있었다. `test_concurrent_ledger_edit_after_read_is_preserved`에서 외부 편집을 실제 주입해 재현하고 읽기 전 토큰을 저장/비교하도록 수정했다.
- F2: 새 observed/recorded/unchanged 결과가 CLI 성공 목록에 연결되지 않아 JSON 성공과 종료2가 함께 나왔다. `test_observation_and_timing_cli_success_exit_codes`에서 inspect·mark·반복 mark·report의 실제 종료 코드를 확인하고 해당 새 명령에만 성공 코드를 연결했다.
- 두 결함은 같은 변경 없는 회귀 파일로 수정 전12개/실패2, 수정 후12개/실패0을 확인했다. 수정 전은 기존 검사 실행기에 명시적으로 좁힌 unittest 명령을 전달한 보고서이며 전체 suite 실행이라고 하지 않는다. 테스트 파일 해시·실패/통과의 실제 사례 ID와 원본 로그를 보존한다.

## 한계

단계 시간은 명시 mark에 따른 경과이며 CPU·모델 사고·병행 작업별 시간을 분리하지 않는다. 이번 개선의 실제 절감 시간은 아직 비교 측정하지 않았다. 무결성 확인·템플릿·지침 등록을 분석 진실성/독립 검토/제품 전체 완료로 확대하지 않는다. 파일 작업은 기존 단일 작성자·낙관적 충돌 검사와 worktree 경계를 유지하며 분산 잠금 보증은 아니다.
