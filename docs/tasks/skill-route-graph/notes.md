# 스킬 라우트 그래프 구현

2026-10-31. 사용자 승인한 그래프 설계: 노드는 스킬:라우트, 이동은 call/return과 transition, 조건은 steps_complete/user_choice/reason. 현재 대화 모델에서 진행하고 모델 추천 라우팅은 별개다.

## 검증 계획

기존 미커밋 스킬 정리·생명주기 훅·계획 변경을 보존한다. 현재 전체 소스의 파일별 해시와 별도 로컬 기준/구현 사본을 만들었다. task/evidence를 정본으로 재사용하고 그래프는 실행 위치·증거 참조·복귀 상태만 저장한다.
등록14개 스킬의 실제 라우트와 문서, CLI의 지속 상태를 확인한다. 정상 경로·call 후 정확한 복귀·callee transition·실패 반환/재진입·조건 미충족/미등록 경로 거부·사용자 질문/답변·근거/입력 변경·반복 한도·동시쓰기/손상·선택 읽기·기존 회귀를 검증한다. 제품 UI 변경이 없어 앱 브라우저 E2E는 수행하지 않는다.

## 설계·진행

작은 상태 전이 실행기를 만들며 모델/셸/외부 도구를 자동 실행하지 않는다. 에이전트가 절차를 수행하고 실제 증거를 연결하면 하네스가 등록된 다음 이동을 판정·저장한다. 문서 읽기 선택과 실행 그래프의 책임을 구분한다.

## 확인한 초안 결함

G1: 호출받은 검증이 failed 상태에서 재계획 노드로 transition한 뒤 그 노드의 passed가 원래 검증 호출의 성공으로 반환됐다. 실패 경로의 맥락과 원래 호출 결과 계약을 함께 관리해야 한다.
G2: 필수 이름 입력이 evidence ID만 저장해 task의 해당 entry를 다른 유효한 파일/해시로 바꾸면 이전 입력으로 받아들였다. 진입 때 entry 서명을 함께 묶고 재진입 전까지 변경을 거부해야 한다.
G3: catalog의 digest가 TOML만 포함해 참조하는 실제 SKILL/절차 본문 변경을 감지하지 못했다. 계약에는 소유 절차의 내용 해시도 포함해야 한다.
기존 프로젝트 결함이 아닌 이번 격리 구현 초안의 경계 결함이다. 같은 회귀 파일을 둔 RED 소스와 실제 실행 보고서를 보존한 뒤 수정한다. 최초 테스트의 /var와 /private/var 사본 경로 불일치는 fixture를 canonical 경로로 고친 테스트 오류이며 제어기 결함과 구분한다.

## 반영 결과

스킬14개를 유지하고 각 routes.toml에27개 라우트, .agents/skill-flow.toml에72개 허용 경로를 선언했다. catalog 검증·지속 상태·실제 CLI를 구현했다. 현재 노드의 절차와 출구 메타데이터만 읽고 공통/프로젝트/보안 문서와 인덱스를 유지한다. 외부 모델/셸/도구 자동 호출은 없다.
절차와 검증을 분리하고 필수 호출·증거 유형·현재 소스/실행 권한을 확인한다. 사용자 질문 ID/선택/원문 증거, 정확한 호출 복귀 위치, callee transition, 실패 경유 반환, 재진입, 입력·절차 계약 변경, 진전 없는 반복·깊이·이동 예산, 잠금/revision/원자적 저장/checksum과 크기 한도를 연결했다. 새 skill create/from-knowledge도 활성 그래프에서 기본 라우트를 생성한다.
현재 source를 기준 사본과 대조해46개 파일을 반영했다. 기존 스킬 정리·훅·top-down 계획 변경을 보존했고 별도 worktree·커밋·푸시·원격 서버를 변경하지 않았다.
