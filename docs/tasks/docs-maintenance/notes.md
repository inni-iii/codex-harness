# 문서 관리 스킬 조사·작성·검증 기록

확인일: 2026-10-31. 공개 docs 사례·위키 사례·레포 연결을 서브에이전트 3개로 병렬 조사했다.
결과와 원문은 [도입 조사](../../../tools/harness/docs/docs-maintenance-research.md), 실제 절차는 [스킬](../../../.agents/skills/docs-maintenance/SKILL.md)에 있다.

## 검증 계획과 범위

- 문서 구조·최신화·위키·검증의 조건부 절차와 발견/선택 연결을 확인한다.
- 스킬 metadata·내부 링크·등록, 양성/음성 context 10개 사례와 합성 문서 작업 3종을 확인한다.
- 앱 동작 변경이 없어 제품 E2E는 수행하지 않는다. 원격 실행·외부 자료 반입·도구 설치를 추가하지 않는다.
- Git 첫 커밋이 없어 worktree 대신 고정 소스 사본과 독립 임시 문서 fixture를 사용했다. 외부 동시 세션의 파일은 수정하지 않았다.

## 확인한 결함 F1: 외부 사례에 잘못 귀속한 링크 삭제 정책

- 증상: 조사 초안이 tomzx의 HTTP HEAD 실패 처리를 외부 링크 자동 삭제로 설명했다.
- 재현 입력: tomzx sync-documentation의 외부 링크 절은 비정상 응답을 broken으로 보고하며, 외부 링크를 자동 편집하지 말라고 명시한다.
- 기대 판정: broken 판정의 한계와 외부 링크 편집 금지를 구분해야 한다. nav의 add-or-flag와 선택적 빌드도 무조건 작업으로 귀속하지 않는다.
- 수정: 조사 표에서 자동 삭제 귀속을 제거하고 HEAD 판정·nav 수정은 현재 하네스에 맞춰 조정한다고 기록했다. 스킬 본문에는 오귀속이 없었다.
- 회귀 시나리오: 같은 원문 입력을 다시 읽고 조사 표가 삭제 정책을 귀속하지 않으며, 실제 스킬이 인증/네트워크 실패를 곧바로 삭제 근거로 쓰지 않는지 대조한다.
- 수정 후 확인: 공개 원문 재열람과 독립 조사 에이전트 검토로 위 판정을 확인했다. 문서 내용·출처의 반례 시나리오이며 가짜 코드 테스트로 대체하지 않았다.

## 병렬 작업과 중간 실패의 범위

- 타 세션이 스킬 3개와 review-rounds 문서를 작성하는 중 전체 catalog/링크 검사가 일시 실패했다. 소유 밖 파일을 임의 등록·삭제하지 않았다.
- 첫 고정 사본의 271개 회귀 검사 중 2개는 당시 미완성 review-rounds 링크로 실패했다. 대상 문서가 완성된 뒤 동일 코드 사본에서 실패한 2개를 재검사해 통과했다.
- 1개 skip은 실행 sandbox의 프로세스 그룹 신호 제한이다. 이를 실행 통과로 바꾸지 않았다.
- 이후 원본 스킬 등록이 완성되어 live doctor와 context 원문 읽기가 정상 동작했다. 최종 검사 기록은 로컬 검증 artifact와 review에 연결한다.

## 독립 문서 작업 결과

- 재구성: 현재 설계 이동·목차/이전 경로/워크플로 갱신, 결정·실패·미결정 보존.
- 동기화: 코드/schema 정적 대조, 1–8/202 queued/401/422 반영. 인증 schema 공백과 과거 검증 한계를 유지. 앱이나 테스트는 이 fixture에서 실행하지 않았다.
- 위키: 서버 1.x/서버 2.x/모바일 2.x 적용 범위와 미결 제품 정책 분리, 출처 지시문 미실행, 과거 오기 정정.
- 보호 파일 9개 hash 유지, 로컬 링크/단순 앵커 32개 오류 없음, workflow 참조 2개 정상. query-only 전후 25개 파일 불변.
- 한계: 합성 입력 3종의 독립 작업이며 일반 성능 평가가 아니다. Markdown 렌더러·실제 외부 source URL·실제 앱 동작은 검증하지 않았다.

## 최종 검토

- 실제 원본에서 doctor·skill validate와 문서 원문 선택 통과. docs 스킬·참조·조사 파일은 통과한 고정 사본과 동일함을 확인했다.
- 최종 고정 사본 등록 검사 doctor/agent-config/secret-patterns/python 통과. Python 272개 실행, 실패 0, 환경 제한 skip 1.
- 검사 중 다른 세션의 라우팅/완료 기능·공유 설명서가 갱신되어 live_source_changed=true다. 전체 최신 소스의 회귀 통과로 확대하지 않고 이번 스킬 범위의 내용과 선택 연결을 별도 확인했다.
- F1 교정과 참조·읽기 조건·권한 범위의 독립 검토 뒤 새 docs 범위 결함을 발견하지 않았다. 원본 자료·병렬 작업을 보존했다.
- 재실행은 레포 루트에서 정상 Python으로 skill validate docs-maintenance, doctor, context --kind review --topic docs-sync --read, check --paths .agents/context.toml --snapshot을 사용한다. 원본 fixture/log는 Git 제외 로컬 검증 artifact이며 다른 노트북에서는 다시 만들어 검증해야 한다.
