# 프로젝트 설명 절차 연결 검토

## 변경과 근거

설명 누적의 정본과 양식은 plan-project에 두었다. 계획·구현·재개와 검증/문서 동기화가 관련 원문을 읽도록 연결한다. 프로젝트에서는 실제 설명 내용이 생겼을 때 architecture/explanation-guide.md 하나를 유지하고 지도/조건부 읽기를 함께 연결한다. 현재 범용 하네스에 특정 서비스 설명 문서를 임의 생성하지 않았다.

중간에는 구조·선택 이유·대안·실패·검증 근거만 누적한다. 최종 정리에서만 현재 코드·결정 원문·검사 결과를 대조해 그 프로젝트의 문답과 필요한 개념을 작성한다. 특정 사례의 문항이나 구체 내용을 양식·테스트·문서에 넣지 않았다.

실행기가 문답을 생성하는 기능을 추가한 것은 아니다. 현재 에이전트가 읽고 수행하는 절차이며 사용자 이해나 평가 성적을 보장하지 않는다.

## 실행 확인

레포 루트에서 `python3 -m unittest discover -s tools/harness/tests -p test_project_explanation.py -v`를 실행해 4건 통과, 실패·건너뜀 0건을 확인했다. 실제 context 원문 선택, request-only flow 진입과 기존 구현 gate, 프로젝트별 조건부 읽기, 같은 경로 갱신과 재개를 검사한다. 원본은 `.runtime/project-explanation/after.log`다.

`doctor`와 `security config`도 확인했다. 초기 라우트 연결의 F1은 검증 라우트가 다른 소유 스킬의 상세 문서를 직접 등록한 오류다. 담당 스킬의 acceptance에서 절차와 원문 링크를 소비하도록 고쳤다. 최종 테스트와 동일한 파일을 사용하는 별도 로컬 사본에 잘못된 등록을 재현해 실제 등록 검사 실패를 보존했다. 위치는 `.runtime/project-explanation/reproduction.json`과 `regression-before.json`에 있다. 현재 작업 폴더는 되돌리지 않았다.

최종 등록 검사 명령은 `python3 tools/harness/run.py check --paths .agents/context.toml .agents/skills/plan-project/routes.toml tools/harness/tests/test_project_explanation.py --checkpoint final`이다. 실제 실행 결과는 task의 check evidence에 연결한다. 문서와 설정/선택 동작 변경이며 제품 UI가 없어 E2E는 비적용이다.

## 작성자 자체 시나리오 대조

아래는 원문·양식·연결을 대조한 자체 검토다. 별도 에이전트나 실제 서비스 구현의 완주 결과로 표현하지 않는다.

| 상황 | 현재 규칙과 확인한 경계 |
|---|---|
| 구현 도중 설명이 늘어남 | 설명만 관련 절에 누적하며 문답은 최종 정리에 한정한다. 양식에도 실제 질문은 없다. |
| 선택 이유 원문이 없음 | 미기록·추론을 구분하고 당시 결정인 것처럼 채우지 않는다. |
| 구조를 바꾸거나 결정을 번복 | 현재 설명을 갱신하고 중요한 이전 선택·날짜·변경 근거를 보존한다. |
| 테스트 파일만 있고 실행하지 않음 | 구현 확인과 실행 확인을 구분하고 미실행은 미확인으로 남긴다. |
| 다른 세션에서 재개 | 지도/프로필의 관련 조건으로 같은 문서를 읽고 현재 소스와 대조한다. 실제 재조회·동일 경로 갱신은 자동 검사로 확인한다. |
| 최종 정리를 요청 | 전체 흐름과 기록/검사 근거에서 새로운 프로젝트별 문답을 도출한다. 이상적 설계를 현재 구현의 답으로 쓰지 않는다. |
| 최종 정리 뒤 코드 변경 | 영향받는 설명/문답을 갱신 필요로 두며 중간에 새 질문을 생성하지 않는다. |
| 짧은 질문이나 프로젝트 미정 | 빈 프로젝트/설명 문서·별도 task를 강제하지 않는다. context 열람만으로 문서를 생성하지 않는 것은 실제 검사로 확인한다. |

## 제한과 다음 사용

자동 검사는 선택·읽기·라우트·경로 재사용을 확인한다. 사람이 이해할 설명의 정확성과 실제 최종 문답 생성 품질은 코드·결정·검사 원문을 대조하는 에이전트 검토가 필요하다. 모의 문답과 사용자 이해 확인은 별도 요청 범위다. 기존 다른 작업의 변경은 보존했으며 그 변경의 제품 품질을 이번 기록으로 승인하지 않는다.
