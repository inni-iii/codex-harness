# 스킬 상세 절차 소유권과 선택 조건 정리

2026-10-31. 사용자 승인: 스킬14개 유지, 학습은 maintain-knowledge, 브라우저 작성/시각/실패는 e2e-testing, 공통 검증은 범위/시점/완료 판단과 연결을 담당한다.

## 검증 계획과 격리

관련 과거 원문과 현재 스킬/참조/선택 코드를 읽었다. 별도 로컬 체크아웃에서 이동·링크·선택 조건을 먼저 검증하고 기준 상태와 대조해 원본에 반영한다.
새10개 선택 시나리오, 기존 workflow/UI/보안/완료 회귀, doctor·구성/비밀값 검사와 실제 읽기량을 확인한다.
앱 동작을 수정하지 않아 제품 브라우저 E2E는 수행하지 않는다. 파일 이동 때문에 보호 조건이나 예제·검사 범위를 낮추지 않는다.

## 확인한 회귀 S1

초기 조건 정리안에서 review 상세 참조를 코드 경로로 선택하게 했더니 review 단계가 아닌 일반 UI 구현에도 코드 리뷰 매뉴얼을 읽었다.
기존 ContextTests.test_small_ui_change_does_not_load_all_new_workflows가 review.md 과잉 선택으로 실패했다. 다른320개 중 환경skip1 외 새 실패는 없었다.
원인: 기존 선택 조건은 kind/topic/path OR여서 코드 경로 조건만 추가하면 단계 조건을 함께 요구할 수 없다.
기대: 일반 UI 구현에는 공통/관련 검증을 유지하되 상세 코드 리뷰는 review 단계와 코드 경로 또는 명시적 code-review 요청이 함께 맞을 때 읽는다.
실패한 초안·변경하지 않은 기존 회귀·실제 실패 보고서를 로컬 red 사본으로 보존하고, 조건 가드를 추가해 동일 테스트의 수정 후 통과와 주변 선택을 확인한다.

## 반영 결과와 선택 읽기

스킬14개를 유지했다. 학습 참조·양식을 maintain-knowledge로 이동하고 현재 링크/선택 조건을 바꿨다. 브라우저 작성 예·시각/접근성·실패/설정은 e2e-testing을 정본으로 삼고 verify-work는 범위·시점·공통 수용 판단과 연결을 맡는다. 양식의 채택 상태는 catalog를 참조해 중복 장부를 피한다.
코드 경로와 명시 주제로 상세 검증을 선택하되 연구·일반 문서에는 과잉 로드하지 않는다. 공통 검증 흐름·발견 처리·보안·task 완료 계약은 남겼다. 리뷰 단계 가드 requires_kinds는 catalog에만 추가했으며 프로젝트 workflow의 기존 OR 계약을 유지했다.

초기 커밋과 별도 정리안에서 같은12개 사례의 선택 원문 글자 수를 측정했다. 일반 문서 편집 14,938→7,399, 문서 검토 19,884→10,848, 학습 검토 18,943→8,402다. 스킬/참조 본문의 Python Unicode 글자 수로, 공통 지침·인덱스·과거 세션·모델 토큰/과금은 포함하지 않는다. 모든 사례가 줄지는 않았다. 코드 작업의 조건 설명은 일부 늘었다. 원문과 조건이 있는 context-comparison.json에 통합 후 수치도 별도로 남겼다.

반영 중 현재 작업 폴더에 별도 생명주기 훅 작업이 들어온 것을 확인했다. context.toml·maintain-knowledge/SKILL.md·AGENTS.md는 기준 커밋과 양쪽 원문을3방향 대조해 합쳤다. 해당 훅 변경·작업 기록·별도 worktree를 덮어쓰지 않았다. 이 요청에서는 새 훅 동작이나 제품 브라우저 E2E 완료를 주장하지 않는다.

## 최종 검증과 한계

통합 snapshot 검사는 doctor·agent-config·secret-patterns·python을 모두 통과했다. 실제342개 테스트, 실패0·환경skip1이다. 그룹 신호를 거부하는 sandbox의 실행기 하위 사례가 skip이며 이번 선택 회귀는 모두 실행됐다. 실행 중 live_source_changed=false, 미룬 검사 없음이다. 스킬14개는 레포 검증과 skill-creator quick_validate를 통과했다. 후자는 프로젝트 venv에 PyYAML이 없어 기존 캐시의 패키지를 읽기 전용 PYTHONPATH로 사용했으며 설치/전역 설정은 바꾸지 않았다.

근거는 task.json과 review.json에서 OWN(당시 소유권/원문 사본), CONTEXT(12개 전후/통합 읽기 결과), RED(S1 실제 실패 보고서), GREEN(최종 실제 검사 보고서)으로 연결했다. 최종 검토는 작성자 자체 검토이고 독립 평가를 주장하지 않는다. 제품 UI를 바꾸지 않았으므로 앱 E2E는 수행하지 않았다. 커밋·푸시·원격 쓰기·다른 worktree 변경 없음.
