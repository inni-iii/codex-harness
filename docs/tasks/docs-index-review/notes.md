# docs 스킬 재점검과 인덱스 연결

확인일: 2026-10-31. 사용자 요청은 docs 스킬 재검토, 주제부터 설계/순차 구현까지의 구조 확인, 인덱스 우선 선택 읽기다.
라우팅 필수 해제는 사용자가 다른 세션에서 진행한다고 명시했다. 이 작업은 직접 진행하며 해당 설정은 수정하지 않는다.

## 범위와 검증 계획

- 작은 최상위 지도와 프로젝트/작업/하네스 하위 지도를 연결한다.
- 일반 docs도 인덱스→선택 본문→필요 근거 순으로 읽고, 누락/오래됨은 좁게 검색한다.
- 새 프로젝트 index 생성과 context 앞 순서/중복/필수 원문 보존/legacy 호환을 실제 코드로 연결한다.
- 주제→조사→설계→구현 순서→기능별 검증→다음 작업을 plan-project로 연결하고 task/evidence를 상태 정본으로 유지한다.
- 앱 기능이 바뀌지 않아 제품 E2E는 수행하지 않는다. 자동 회귀·문서 링크/선택·독립 합성 문서/단계 전환을 확인한다.
- 첫 커밋 없는 레포라 코드 변경은 별도 소스 사본에서 검증하고 원본 바이트가 그대로인지 확인한 뒤 반영했다. 다른 세션 변경을 덮어쓰지 않았다.

## 실제 발견과 수정

### D1: 현재 docs 상태 안내 오류

예전 README는 tasks가 첫 작업 때 만들어진다고 했지만 실제 기존 task/notes가 있었다.
현재 안내를 고치고 탐색용 작업 인덱스로 연결했다. 수정 전 원문과 재사용 반례는 로컬 D1 artifact에 보존했다.

### D2: 초기 완료 artifact가 현재 스킬 변경을 막음

docs SKILL을 보완하자 이전 완료 E1의 mutable 경로/hash 불일치로 doctor가 실패했다.
초기 bytes가 E1 hash와 정확히 같은지 확인하고 초기 내용/해시는 유지한 채 보존 사본으로 경로를 옮겼다.
초기 task의 review digest/hash와 보관 이유를 갱신했다. 초기 완료를 새 스킬 검증으로 바꾸지 않았다.
doctor 재검사 통과. 이 반례/전후 관측은 별도 로컬 artifact에 남겼다.

## 추가된 연결과 한계

- docs/index는 작은 영역 지도이고 하네스 개별 문서는 tools/harness/docs/index, 작업 기록은 docs/tasks/index에서 선택한다.
- context는 인덱스를 한번 포함하지만 링크를 자동 재귀로 펼치지 않는다. --paths는 규칙 입력이며 직접 파일 읽기가 아니다.
- project는 index/brief/security/workflow만 만든다. 미래 설계/계획 문서의 빈 stub·가짜 링크는 만들지 않는다.
- 설계/계획은 필요한 때 작성하고 실제 task의 선행 조건·입력 계약·완료 근거를 확인해 다음 작업을 고른다. 자동 DAG/제품 전체 자동 구현은 추가하지 않는다.
- 새 동작의 5개 요구 기반 테스트는 기존 코드에서 4개 실패/1개 호환 통과를 관측하고 구현 뒤 5개 모두 통과했다. 이후 경로 이탈 거부도 포함한 6개 회귀가 통과했다.
- 인덱스는 필수 문서·보안/세션 원문을 대체하지 않는다. 문자량 비교를 실제 모델 토큰·비용·정확도 보장으로 표현하지 않는다.

## 최종 확인

- 고정 사본 doctor·agent-config·secret-patterns·python 통과. Python 313개 실행, 실패 0, 환경 제한 skip 1. 검사 완료 시 live_source_changed=false였다.
- 별도 관련 검사: 신규 인덱스 6개, 기존 workflow 32개, layout 2개 통과. 하네스 지도는 현재 Markdown 27개를 모두 연결한다. 최상위 지도 본문은 1,058자다.
- 독립 탐색 사례는 fixture docs 10개/182,951바이트 중 관련 5개/2,237자·바이트만 읽었다. 공통 스킬/과거 원문 비용 제외이며 토큰 절감률이 아니다. 읽기 전용 원본 11파일에 변경/추가가 없다.
- 독립 순차 사례는 잘못된 인덱스 링크를 좁은 검색으로 보완하고 설계/계획/현재 근거에서 준비된 S1만 구현했다. 기존 4개 테스트를 바꾸지 않고 실패→통과를 확인했다. 다음 S2는 HTTP 계약 필요로 남겼고 전체 프로젝트를 완료 처리하지 않았다.
- 요구·설계·연구·테스트 원본 6개 SHA 유지, 관련 문서 링크 14개 정상. 합성 단위 동작의 결과이며 실제 서비스·API/UI 통합 검증이 아니다.
- 독립 최종 검토와 부모의 요구·경계·근거 재대조에서 이번 범위의 추가 결함을 발견하지 않았다. 완벽성·모든 서비스의 자동 수행·토큰/비용 절감을 보증하지 않는다.
