# 목표에서 작업으로 이어가는 계획 보강

2026-10-31 사용자 결정에 따라 기존 plan-project를 보완했다. [프로젝트 진행 절차](../../../.agents/skills/plan-project/references/project-lifecycle.md)가 판단의 정본이고, [계획 양식](../../../.agents/skills/plan-project/assets/project-plan.md)은 필요할 때 기존 프로젝트 계획에 적용한다.
새 스킬·JSON 필드·자동 실행기·훅을 추가하지 않았다. task/evidence의 기존 상태와 결과 정본을 유지한다.

## 요구와 변경의 연결

| 기준 | 반영한 내용 | 확인 위치 |
|---|---|---|
| A1 역할·범위 | 사람의 Charter·아키텍처 경계·마일스톤·작업 요청, AI의 요구 도출·작업 분해/배정·구현·검증. 추론한 요구와 제품 제안 구분, 세부 단계의 반복 승인 방지 | 프로젝트 진행의 목표와 실행의 역할 |
| A2 갭 재평가 | 마일스톤→요구/성공 조건→현재 근거→갭→작업→검증. 시작 때 이전 평가/현재 근거 비교, 종료·중단 때 결과·잔여/새 갭과 다음 행동 연결 | 프로젝트 진행, 계획 양식, verify-work와 인수인계 |
| A3 경계 | 미구현/미검증/불충족/차단/결정 대기, 목표 변경의 기준 보존, 과거 완료 이력 보존, bottom-up 발견 처리, 작은 요청의 축소 절차 | 프로젝트 진행의 갭·시작·종료 절과 양식 |
| A4 발견·사용 연결 | AGENTS·스킬 본문·context 주제/경로·개요/계획/인수인계·생성 인덱스·문서 지도를 연결 | context 실제 선택, project 생성 사본, 관련 기존 검사 |

## 수동 시나리오 검토

아래는 작성자가 절차를 실제 사례에 대입한 자체 검토다. 독립 모델 평가나 실행되지 않은 제품 테스트를 뜻하지 않는다.

| 입력·상황 | 절차를 적용한 판단과 산출물 | 관측/판정 |
|---|---|---|
| M1은 저장 후 재조회. 이전 G1은 저장 없음. 현재 저장 동작은 코드에 있지만 검증이 없음 | G1을 미구현에서 미검증으로 구분. 우선 저장/재조회 검증을 작업으로 선택, 실제 결과 전 충족 선언 보류 | 재구현이나 근거 없는 완료를 피함 |
| 이전 task는 complete지만 이후 공유 계약이 변경됨 | 과거 task 이력은 유지. R1 현재 충족은 미확인으로 재평가하고 변경 영향의 검사 선택 | 과거 완료 삭제/맹신을 피함 |
| 요청은 G1 검증인데 상관없는 G2 기능 부족 발견 | G2를 잔여/후속 후보로 연결하고 요청한 G1을 수행. G1을 막는 의존성이면 그 영향을 먼저 설명 | 목표만으로 전체 backlog에 착수하지 않음 |
| 사람이 성공 조건을 로컬 저장에서 동기화로 변경 | 변경 결정·새 기준을 연결. 이전 로컬 결과와 근거를 보존하고 새 갭의 기준선 작성 | 다른 조건을 갭 감소/진척률로 섞지 않음 |
| 환경 의존성을 사용할 수 없음 | 구현/요구 불충족과 구분해 차단 범위·필요 전제·다음 확인을 기록. 가능한 독립 범위만 진행 | 환경 부족을 통과로 바꾸지 않음 |
| 구현 중 권한 문제 발견 | 관련 요구/갭과 현재 흐름 영향을 연결. 요청 범위의 회귀/보안 수정은 처리하고 목표/주요 경계 변경은 영향·대안을 제안 | bottom-up 발견을 숨기거나 임의 목표로 승격하지 않음 |
| 작업들이 모두 complete지만 상위 성공 조건 일부가 어떤 작업에도 없음 | 수용 기준과 상위 조건의 대응을 대조해 누락 갭을 추가. 마일스톤 달성은 보류 | 작업 수/완료 상태를 목표 달성과 혼동하지 않음 |
| 프로젝트 없는 짧은 질문·작은 수정 | 요청 자체의 목표/기준과 관련 변경만 확인. Charter·마일스톤·별도 계획을 만들지 않음 | 계획 문서와 전체 재검사를 강제하지 않음 |

계획 양식은 요구·현재 관측과 task/evidence 원문을 연결한다. 완료 목록·진척률·요구의 정본을 중복 작성하지 않는지 검토했다.
프로젝트 개요와 생성 인덱스에는 없는 plan 파일 링크를 만들지 않았다. 별도 계획이 생긴 경우에만 실제 정본과 context 규칙을 연결한다.

## 실행한 검증

- 레포 skill validate: plan-project, verify-work 통과. doctor와 diff 공백 점검 통과.
- 실제 context 선택8사례: top-down 계획, 구현 전 gap-analysis, 마일스톤 검토, plan.md 경로는 절차 선택. 작은 문서 편집·일반 연구·단순 디버깅·학습은 해당 상세 절차 미선택.
- 임시 레포에서 실제 project 생성: brief/index/security/workflow 네 파일만 생성, draft 유지, 별도 plan 파일 불필요, 생성 후 doctor 통과.
- 기존 test_skill_scopes/test_workflows/test_skills/test_document_indexes:51개 통과. 새 문구 일치 테스트를 추가하지 않았다.
- 시스템 skill-creator의 quick_validate는 PyYAML 모듈이 없어 실행하지 못했다. 의존성을 추가 설치하지 않았고, 현재 사용한 두 필드의 최소 스킬 형식은 레포 검사기로 확인했다.

## 한계와 권한

지침·양식·선택 설정을 적용한 상태다. 매 요청의 의미상 갭 판단과 계획 갱신은 에이전트가 관련 원문/근거를 읽고 수행한다. 자동 스케줄러·자율적인 목표 변경·멀티에이전트 실행을 구현했다는 뜻은 아니다. 모델의 장기 성과나 독립적 계획 품질을 측정하지 않았다.
다른 스킬 정리 작업의 변경을 보존하며 이번 델타만 통합한다. 커밋·푸시·원격 서버 작업·전역 설정 변경은 하지 않는다. 제품 UI 변경이 없어 브라우저 E2E는 비적용이다.
