# 문서 지도 검증 사례

| 요구 | 확인한 사례·결과 | 한계 |
|---|---|---|
| 폴더와 파일별 지도 | 문서 폴더 index 누락, Markdown 링크·역할 누락, 하위 지도 누락과 이동 뒤 오래된 링크를 거부한다 | 역할 문장의 사실성은 자체 문서 검토가 맡는다 |
| 실제 항목 | 코드 블록·인라인 코드·주석·TODO·링크만 있는 항목을 인정하지 않는다 | 일반 Markdown inline 링크의 표/목록 형식을 계약으로 사용한다 |
| 경로 | 공백/퍼센트 인코딩·상대 경로를 지원하고 symlink/루트 탈출을 거부한다 | 외부 URL 접근·Markdown 렌더러별 앵커 검사는 이번 범위 밖이다 |
| 생성과 재개 | 새 task/project 지도와 상위 링크를 생성하고 기존 지도 본문·기존 폴더를 덮어쓰지 않는다 | 이후 새 Markdown은 작성자가 index를 함께 갱신한다 |
| 선택 읽기 | 선택한 중첩 API 문서의 조상 지도만 본문보다 먼저 읽고 무관한 운영 지도·큰 본문을 제외한다 | 합성 fixture이며 실제 모델 토큰·정확도 절감률을 측정하지 않았다 |
| 프로그램 읽기 | 감사기가 파일 이름과 index만 읽는지 read_text 감시와 파일 바이트 전후 비교로 확인했다 | doctor의 기존 구문/링크 검사는 별도로 원문을 읽지만 이를 모델에 주입하지 않는다 |

수정 전 등록 검사: 454개, 실패/오류 18·skip 1. 그중 기존 doctor가 index 누락을 보고하지 않는 안정된 회귀가 F1의 실제 재현이다. 나머지 신규 모듈 미구현 오류를 별도 제품 결함으로 세지 않는다.
격리 구현 뒤 등록 검사: 456개, 실패 0·skip 1. 인덱스 관련 19개는 모두 실행됐다. skip은 기존 process group 권한 제한이다. 통합 뒤 현재 상태 검사는 task evidence로 연결한다.
