# 실제 데이터 분석과 연결 확인

작성 에이전트가 만든 합성 데이터의 확인이며 실제 사용자 데이터나 독립 모델 평가가 아니다.

## CSV: 지표별 분모와 집단 구성

원본은 BOM·따옴표 안 줄바꿈·앞의0이 있는 ID를 포함한24개 논리 레코드다. 선언한 단위는 기간 내 사용자1명당1행이다. 완전히 같은 중복1개를 제거해23명을 확인했다. 채널이 없는1명은 채널 비교에서 제외하고22명을 분석했다. 금액이 잘못된1명은 전환 필드가 유효하므로 전환율에서는 유지했다.

| 집단 | A 전환/분모 | B 전환/분모 | 관측 |
|---|---|---|---|
| 전체 채널 비교 | 6/11 | 7/11 | B의 전체 비율이 높음 |
| easy | 5/6 | 7/10 | A의 비율이 높음 |
| hard | 1/5 | 0/1 | A의 비율이 높지만 B 표본은1명뿐 |

층별 방향과 전체 방향이 뒤집히는 실제 계산을 확인했다. 집단의 난이도 구성 차이를 무시하고 B 채널의 인과적 효과가 좋다고 결론내리지 않았다. 실제 정책 선택에는 대상 집단·노출·비교 설계와 불확실성 검토가 더 필요하다.

금액을 읽을 수 있는22명의 알려진 금액 소계는1,300이다. 금액 오류1건이 있어 이를 전체 매출로 부르거나0 대체하지 않았다. 매출 오류를 이유로 유효한 전환 레코드까지 전역 제거하면 비교 지표의 분모가 달라지는 반례를 보존했다.

## JSON: 부모/자식 단위와 합계

중첩 주문 JSON은 부모 주문3개·총액200, 항목3개다. 항목이 없는 주문1개를 포함한다. 단순 inner 배열 전개 후 부모 금액을 합하면260이고, 부모 주문도2개만 남는다. 부모 총액200과 다른 단위를 확인해 주문/항목 표를 분리하고 부모 주문 키/합계·빈 배열 보존을 확인했다.

## 재현과 원본 보존

각 레포 루트에서 표준 라이브러리만 사용해 `.runtime/research-data-analysis/analyze-fixtures.py`를 실행했다. 입력 해시·처리/제외 건수·실제 결과와 불확실성은 `.runtime/research-data-analysis/analysis-output.json`에 보존했다. 원본 두 파일의 SHA-256이 분석 전후 동일함을 확인했다. 원본 값을 명령으로 실행하지 않았다. 추론 검정·모델 학습·인과 효과·실제 서비스 성능은 측정하지 않았다.

선택/flow 검사는 데이터 주제4종의 실제 참조 선택, 일반 JSON 설정/다른 연구의 비선택, plan→분석 원문 읽기→부모의 미완료 단계 복귀, 근거 없는 성공 판정 거부를 실행했다. 이는 절차의 발견/연결 근거이며 에이전트의 모든 통계 판단 정확성을 자동 증명하지 않는다.
