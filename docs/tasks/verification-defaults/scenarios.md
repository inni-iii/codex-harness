# 기본 검증의 자체 시나리오 대조

작성 에이전트의 자체 검토다. 실제 context/flow 호출과 실행 결과를 적고, 자연어 자동 인식의 독립 모델 평가로 표현하지 않는다.

| 사례 | 적용 판단 | 실제 근거/한계 |
|---|---|---|
| S1: “검증해줘”, 대화에 현재 결과물이 있음 | 범위를 재질문하지 않고 기본 계약의 적용 항목을 선별한다. | topic/path 없는 실제 review context가 acceptance 원문을 선택한다. request-only flow 시작과 기존 수리/구현 gate는 자동 회귀로 확인했다. |
| S2: “문서만 확인해줘. 코드는 수정하지 마” | 원문/링크/명령을 대조하고 앱 기동·제품 E2E는 비적용. 수정 금지를 유지한다. | 실제 문서 context는 기본 계약·문서 스킬을 선택하며 제품 E2E를 선택하지 않는다. 명시 제한 해석은 현재 에이전트의 절차 판단이다. |
| S3: Svelte/API 기능을 “검증해줘” | 실제 결과 흐름과 관련 정상·실패/회귀 및 E2E가 필요하다. | 실제 frontend 경로 context에서 E2E 스킬이 선택된다. 이 작업에 실제 제품 UI가 없어 제품 E2E 수행/통과를 주장하지 않는다. |
| S4: 권한 코드 검증 | 허용/거부·입력/자원 권한·비밀·회귀를 실제 경계에서 확인한다. | 실제 auth 경로/보안 topic은 security 스킬/상세 원문을 선택한다. 선택 사실만으로 보안 통과를 주장하지 않는다. |
| S5: 앱 검사가 없음 | 현재 앱 연결 부족을 표시하고 하네스 자체 통과로 바꾸지 않는다. | 실제 미등록 frontend/NewForm.svelte 선택은 uncovered로 남는다. 새 앱/도구를 설치하지 않았다. |

현재 변경은 네이티브 스킬/참조·선택/flow·문서다. 실제 context 원문·정상/거부 flow와 기존 관련 회귀를 실행하고 전체 등록 검사로 검증한다. 구조는 기존 verify-work 단일 소유와 전문 스킬 위임을 유지했다. 새 자동 모델/도구 호출·hook 이벤트·권한 확대·서버·제품 코드는 추가하지 않았다. 현재 명시 제한과 범위를 우선하며 작은 문서/질문마다 앱 전체 suite를 요구하지 않는다.
