# 문서 구조와 독자의 읽기 흐름

파일 분류·목차·중복 정리·병합·분할·이동 또는 문서 구조 감사를 할 때 읽는다.
읽기 편해진다는 이유로 결정·실패 기록·예외를 삭제하지 않는다.

## 기존 문서 지도를 먼저 만든다

- 먼저 [인덱스 선택 읽기](navigation.md)로 질문에 맞는 지도·정본만 고른다. 광범위 구조 감사가 아닌 요청에서 전체 문서 본문을 먼저 로드하지 않는다.
- 실제 문서 위치와 진입점, 사이트가 있으면 navigation 설정·링크 형식·렌더러를 확인한다. 숨김 지침·스킬 참조·코드 주석·생성 입력도 관련 범위에서 찾는다.
- 페이지마다 독자, 해결할 질문, 현재/초안/과거 여부, 근거·정본 위치를 확인한다. 모든 파일에 새 frontmatter를 강제하지 않는다.
- 외부에서 들어오는 경로, 문서 간 참조, 프로젝트 워크플로·도구가 읽는 경로를 찾는다. 파일명이 비슷하다는 이유로 중복으로 판단하지 않는다.
- 의존성·캐시·출력물은 내용 감사에서 제외하되, 요청한 원본이나 결정이 과거 자료에만 있으면 해당 자료까지 확인한다.

규모가 크면 `경로 → 독자/목적 → 현재 상태 → 연결/근거 → 조치` 표로 영향 범위를 정리한다.
한 문장 수정에 전체 파일 목록이나 관리 문서를 새로 만들지 않는다.

## 독자가 하려는 일로 분류한다

| 독자의 필요 | 문서가 제공할 내용 |
|---|---|
| 처음 배우기 | 끝까지 따라갈 수 있는 작은 실습과 확인 결과 |
| 특정 문제 해결 | 전제·행동 순서·성공 확인·실패 시 다음 행동 |
| 정확한 정보 조회 | API·옵션·기본값·반환·제약의 일관된 명세 |
| 이유와 배경 이해 | 선택 이유·대안·조건·장단점·근거 |

이 구분은 기존 구조를 판단하는 기준이다. 네 가지 폴더나 페이지를 의무로 생성하지 않는다.
절차에 긴 배경이 끼어 흐름을 막으면 설명 문서로 연결하고, 참조 정보가 여러 곳에 복제되면 정본 하나를 정해 링크한다.
결정·실험·운영 기록처럼 날짜와 상태가 중요한 문서는 그 역할을 유지한다.

## 병합·분할·이동

1. 기존 절의 주장·조건·예외·원본·실패 이유를 비교한다. 같은 결론이어도 적용 버전이나 시점이 다르면 차이를 보존한다.
2. 실제 혼란을 줄일 때만 병합·분할한다. 문서 길이·고정 글자 수만으로 나누지 않는다. 한 페이지의 독자·질문이 달라지는 지점을 기준으로 삼는다.
3. 이동 전에 이전 경로/제목/앵커와 새 목적지를 대응시킨다. 본문 링크뿐 아니라 navigation·include·이미지·스크립트·스킬·workflow 설정의 참조도 갱신한다.
4. 순서가 바뀌면 번호·목차·본문의 절 번호도 함께 맞춘다. 제목 변경으로 생긴 앵커를 확인한다. 외부 공개 주소에는 기존 사이트의 redirect/alias 방식을 사용하고, 렌더러를 모르면 지원을 가정하지 않는다.
5. 중복 제거 후 각 원본의 고유한 내용과 출처가 남았는지 대조한다. 원본 자료·검증 로그·과거 세션은 편집/삭제하지 않는다. 작성 중인 타 세션 파일을 임의로 통합하지 않는다.
6. 옛 문서를 남길 때는 상태·대체 문서·유효했던 시점을 표시한다. 이력이 남았다는 이유로 현재 목차에서 정본처럼 노출하지 않는다. 원문 삭제가 필요한 경우에는 보존 의무·현재 요청·복구 가능성을 먼저 확인한다.

외부 링크나 출처 URL은 로컬 폴더 이름 치환의 대상으로 삼지 않는다.
내용을 합쳤다는 설명만 남기고 옛 문서를 지우지 말고, 옮긴 내용의 대응 관계를 실제로 확인한다.

## 새로 쓰거나 읽기 쉽게 다듬기

- 독자가 얻을 결과와 필요한 전제를 먼저 적는다. 제목·링크 문구는 목적지가 무엇인지 설명하고, 같은 개념은 같은 이름으로 쓴다.
- 실행 절차에는 실행 위치·필요 권한·입력·예상 결과를 적고, 예제 값과 실제 기본값을 구분한다. 명령 자체의 검증은 [검증 절차](validation.md)를 따른다.
- 예외·오류·복구 방법을 정상 절차와 연결한다. 표는 비교·명세에, 번호는 순서에 사용한다. 코드에는 언어를 표시하고 생략은 실행 가능한 전체 예제처럼 보이지 않게 적는다.
- 제목 계층·서술·이미지 대체 텍스트·링크를 확인하고 현재 프로젝트 언어와 스타일을 유지한다. 문구 정리 때문에 제품 용어·계약의 강도를 바꾸지 않는다.
- 링크 확인이나 렌더링 성공으로 내용의 사실성까지 검증됐다고 하지 않는다.
