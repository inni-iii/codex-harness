# 의존성 채택·설치·취약점 검토

패키지를 추가하거나 manifest·잠금 파일·설치 방식·실행 도구를 바꿀 때 읽는다.
버전 고정은 재현성을 높이지만 안전성·출처·알려지지 않은 취약점까지 보증하지 않는다.

## 채택 전에

현재 코드와 표준 라이브러리로 해결 가능한지, 새 의존성이 필요한 이유를 확인한다.
필요하면 공식 문서·공식 저장소·패키지 레지스트리의 연결을 대조해 이름·소유자·유지보수 상태·라이선스·지원 버전을 확인한다.
유사 이름·오타·최근 소유권 변경·이례적인 의존성 증가·설치 스크립트는 검토 근거다. 다운로드 수 하나로 안전을 판정하지 않는다.
모델이나 검색 결과가 제안한 패키지는 실제 존재와 공식 출처를 확인하기 전 설치하지 않는다.

Python의 build backend와 소스 배포 설치, npm lifecycle script는 코드를 실행할 수 있다.
설치 전에 실행 경로·쓰기 위치·네트워크·필요한 비밀값을 확인한다. 진단을 위해 운영 자격 증명을 넘기지 않는다.
새 도구는 레포 로컬에 버전·잠금·설치 안내를 남긴다. npx latest·전역 설치·자동 fix를 검사 명령으로 숨기지 않는다.

## 변경을 읽는 방법

- 직접 의존성 변경 이유와 실제 사용하는 기능을 확인한다. 불필요한 패키지를 보안 도구라는 이유로 추가하지 않는다.
- 잠금 파일에 추가/삭제/버전 변경된 전이 의존성과 resolved 출처·integrity·Git 참조·로컬 경로·설치 스크립트를 확인한다.
- manifest와 잠금의 불일치는 확인 필요다. 검사 과정에서 임의로 lock을 재생성하지 않는다.
- 설치한 실제 환경과 lock이 다르면 둘의 근거를 구분한다. lock 조회 결과로 설치 환경까지 같다고 주장하지 않는다.
- 업그레이드가 필요하면 최소 변경 범위를 정하고 호환성·권한·핵심 흐름을 재검증한다. 자동 수정 결과를 무검토로 채택하지 않는다.

## 알려진 취약점 조회

[로컬 도구](../../../../tools/harness/docs/security.md)의 dependencies 명령은 명시한 입력에 대해 외부 advisory 서비스를 조회한다.
네트워크 동의 옵션은 패키지 이름·버전 메타데이터가 외부 서비스에 전달됨을 뜻한다. 코드·비밀값·원본 사용자 자료를 전송하지 않는다.
사설 패키지 이름도 민감할 수 있다. 공개 레지스트리 어댑터에 사설 의존성을 무심코 보내지 않는다.
기본 check --full에는 네트워크 조회를 넣지 않는다. 서비스의 실제 manifest/lock 경로를 별도로 명시한다.

npm 어댑터는 package-lock v2/v3의 공개 npm 패키지 스냅샷을 설치 없이 조회한다.
Python 어댑터는 모든 전이 의존성을 포함해 이미 정확한 버전으로 펼친 requirements만 받으며 pip resolver·설치를 끈다.
현재 어댑터가 지원하지 않는 uv.lock·다른 lock·VCS·editable·마커·hash 연속행·다른 레지스트리는 설정 필요로 남긴다.
지원하지 않는 입력을 부분 파싱해 일부만 조회한 뒤 전체 성공이라고 하지 않는다. 필요 시 해당 형식의 검증된 어댑터를 추가한다.
하네스 자체 Python 런타임은 현재 표준 라이브러리만 사용하므로 아직 없는 제품의 Python 의존성을 조회했다고 보고하지 않는다.

## 결과를 판단하고 수정한다

조회 시각·도구 버전·대상 파일 해시·종료 코드·조회 패키지 수·후보 취약점 수를 남긴다.
도구 누락, timeout, 네트워크 실패, JSON 형식 변경, 건너뛴 패키지, 0개 대상은 발견 없음과 다르다.
네트워크 조회는 advisory DB가 바뀌므로 오프라인 코드 검사와 동일하게 무기한 캐시하지 않는다.

후보별로 영향 버전·실제 사용 경로·실행 위치·공격 전제·수정 버전·임시 차단을 확인한다.
직접/전이·개발용/실행용은 맥락이며 devDependency라는 이유만으로 무해하다고 제외하지 않는다.
오탐/적용 제외에는 대상 advisory·정확한 버전·근거·재검토 조건을 남긴다. 심각도 기준을 낮추거나 전체 경고를 숨겨 녹색으로 만들지 않는다.
알려진 CVE 0개는 악성 패키지·설치 스크립트·출처 위조·미공개 취약점까지 검사했다는 의미가 아니다.

명령 의미는 [npm audit](https://docs.npmjs.com/cli/v11/commands/npm-audit/), [pip-audit](https://github.com/pypa/pip-audit)를 확인했다. 실제 도입 버전에서 다시 검증한다.
