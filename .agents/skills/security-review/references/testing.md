# 부정 테스트·발견·수정 검증

공격 문자열을 많이 나열하는 것보다 보호해야 할 동작과 관측 가능한 부작용을 연결한다.
[검사 행렬](../assets/test-matrix.md)과 [발견 양식](../assets/finding.md)을 실제 프로젝트에 작성한다.

## 실행 전 조건

대상은 현재 승인된 로컬 앱·테스트 DB·격리된 외부 API 대역이다. 운영 계정·실제 사용자 데이터·실제 과금·외부 사이트 공격을 사용하지 않는다.
서버 시작·테스트가 원격 DB/메일/결제에 연결되지 않는지 먼저 확인한다. URL이 localhost여도 내부 설정은 별도 점검한다.
로컬 부작용은 임시 디렉터리·독립 테스트 사용자·전용 DB로 제한하고 테스트 종료 후 정리한다.
악성 명령은 실행 대신 별도 sentinel 파일/가짜 실행기에서 호출이 없음을 확인한다.

## 사례를 정하는 순서

1. 사용자 요구·위협 모델에서 보호 조건을 쓴다. 예: 비소유자 수정으로 DB 값이 바뀌지 않는다.
2. 정상 사례를 먼저 둬서 모든 요청을 막기만 하는 구현도 실패하게 한다.
3. 관련된 비정상 입력·권한·시간/크기 경계·중복·실패를 고른다. 다른 ID, 직접 HTTP, 다운로드/검색 같은 우회 경로도 고려한다.
4. 예상 응답과 금지할 부작용을 함께 단언한다. 응답 403인데 이미 저장됐다면 실패다.
5. mock은 외부 서비스나 실행 호출을 대체한다. 검사할 인증/권한 함수를 True/False로 바꾸어 실제 경계를 제거하지 않는다.
6. 합성 키·고유 표식을 넣어 정상/오류 로그·trace·보고서·사용자 응답에서 값이 노출되지 않는지 확인한다.

| 경계 | 정상 대조군 | 부정/경합 사례 | 부작용 증거 |
|---|---|---|---|
| 자원 권한 | A가 A의 자원 조회/수정 | B가 A의 ID 요청, body owner 변조, 미인증 | 데이터·다운로드·캐시가 경계를 넘지 않음 |
| 세션 | 유효 자격 | 만료·폐기·변조, 로그아웃 뒤 재요청 | 보호 작업과 세션 재사용 차단 |
| 입력 | 유효 최소/최대 경계 | null/누락/타입·길이 초과, 추가 필드 | 저장·프로세스·외부 요청이 없음 |
| 파일 | 허용 파일 | 위장 형식·경로 탈출·압축 과대·크기 초과 | 승인 루트 밖 파일과 실행 없음 |
| 외부/모델 응답 | 일치하는 schema·ID | 가짜 지시·다른 사용자·잘못된 JSON·부분 오류 | 추가 호출·설정 변경·비밀값 출력 없음 |
| URL | 승인 목적지 | 내부 주소·리다이렉트·userinfo | 격리 transport에서 목적지 차단 |
| 상태 변경 | 한 번 정상 완료 | 중복·동시·timeout 뒤 재시도 | 합의한 횟수만 처리·일관된 상태 |
| 실행 검사기 | 유효 응답 | 도구 없음·오류·빈 결과·거짓 녹색 | 오류가 통과로 승격되지 않음 |

## 실행·재현·수정

대상 코드 상태·명령·cwd·환경 전제·종료 코드·실행/실패/skip 수를 남긴다.
도구 자체 테스트, 가짜 스캐너 응답 테스트, 실제 advisory 조회, 앱 통합 테스트, 실제 브라우저/모델 평가를 구분한다.
실행할 사례가 없거나 전부 skip이면 검증 미완료다. 테스트용 더미 앱의 성공을 제품 성공으로 보고하지 않는다.

실패는 최소 입력과 관측 결과로 재현한다. 공격 입력 원문에 실제 키/개인정보가 있으면 안전한 합성 값으로 대체한다.
발견에는 영향 경로와 주체·공격 전제·신뢰도·심각도 근거를 쓴다. 단순 경고와 재현된 결함을 분리한다.
수정 후 같은 재현으로 차단을 확인하고 정상 대조군과 관련 우회/주변 기능도 다시 실행한다.
가능하면 수정 전 실패·수정 후 통과를 모두 확인하되, 위험한 외부 재현을 위해 취약 코드를 다시 가동하지 않는다.

미해결 발견은 ID·영향·임시 제한·담당 결정·재검증 조건과 함께 열린 상태로 남긴다.
요구를 바꾸거나 실패 테스트를 삭제/skip해 통과시키지 않는다. 수용 가능한 위험의 제품 결정은 에이전트가 임의 확정하지 않는다.

브라우저가 관련되면 [E2E 스킬](../../e2e-testing/SKILL.md)을 이용해 실제 사용자 흐름을 확인한다.
서버 권한은 브라우저 UI와 별개로 직접 API에서도 검사한다. 최종 완료 근거의 공통 판정은 [verify-work](../../verify-work/SKILL.md)를 따른다.
