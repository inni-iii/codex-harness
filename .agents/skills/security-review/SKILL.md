# 설계부터 수정 검증까지 보안 관리

이 레포의 보안 절차는 이 스킬에서 시작한다. 별도의 보안 설계자·구현자·리뷰어 스킬을 중복 생성하지 않는다.
설계 결정은 프로젝트 문서에, 실제 방어는 제품 코드·실행 권한에, 검증 근거는 테스트와 보고서에 둔다.
이 스킬이나 스캐너 통과는 취약점 부재를 보증하지 않는다.

## 현재 단계에 맞게 수행한다

| 단계 | 이 스킬에서 수행할 일 | 연결할 상세 자료 |
|---|---|---|
| 설계 중 | 보호 자원·위협·주체별 권한·데이터 흐름·실패 정책을 정한다. | design과 새로 생기는 경계의 참조 |
| 구현 중 | 실제 언어·프레임워크·기능에 맞는 방어를 서버/실행 경계에 적용하고 관련 언어 스킬과 함께 검토한다. | application, tool-responses, dependencies 중 해당 자료 |
| 구현 후 | 입력에서 보호 자원까지 공격 가능한 경로와 실제 정상/부정 테스트 결과를 대조한다. | 해당 경계의 참조와 testing |
| 결함 발견 | 안전한 최소 재현 → 수정 → 같은 재현과 정상·주변 회귀 검증으로 연결한다. | testing과 발견 사항 양식 |

단계마다 다른 보안 스킬로 전환하지 않는다. 아래 references는 이 스킬의 조건별 상세 자료이며 별도 스킬이 아니다.

## 먼저 작업의 경계를 정한다

1. 현재 요청·변경 코드·프로젝트 보안 문서에서 보호할 자원, 입력 주체, 허용할 행동을 확인한다. 보안 영향이 없으면 이유를 짧게 남기고 일반 작업을 이어간다. 문구 수정에 전체 보안 감사를 붙이지 않는다.
2. 새 서비스나 민감한 기능이면 신뢰 경계와 **항상 유지해야 하는 조건**을 구현 전에 적는다. 예: “사용자 B는 A의 문서 ID를 알아도 내용을 읽거나 바꾸지 못한다.” 위협 목록만 쓰고 보호 동작을 비워 두지 않는다.
3. 입력→파싱→검증→권한 판단→저장/외부 호출→출력 경로를 실제 코드와 대조한다. 경로명에 auth가 없더라도 자원 접근·도구 실행·모델 출력이면 관련 경계를 검토한다.
4. 요구에서 정상·거부·오류·경합 사례를 고른 뒤 실제 처리 경계에서 실행한다. 실패 응답뿐 아니라 데이터·파일·외부 호출·로그에 금지한 부작용이 없는지도 확인한다.
5. 발견→수정→같은 재현과 주변 회귀 검사로 연결한다. 오류·누락·미실행·미해결을 발견 없음으로 합치지 않는다. 최종 결과에는 확인 범위와 남은 조건을 명시한다.

## 상황별 상세 원문

| 지금 필요한 일 | 읽을 자료 |
|---|---|
| 새 서비스·큰 기능·새 데이터/권한/외부 경계 | [위협 모델과 설계](references/design.md) |
| 인증·자원 권한·입력·파일·브라우저·로그 구현/리뷰 | [애플리케이션 경계](references/application.md) |
| MCP·외부 API·검색·모델 응답·자동 도구 호출 | [도구 응답과 실행 권한](references/tool-responses.md) |
| 패키지 채택·잠금 변경·설치 스크립트·알려진 취약점 | [의존성](references/dependencies.md) |
| 공격성 입력·실제 재현·결과 판정·수정 후 재검증 | [부정 테스트와 발견 사항](references/testing.md) |
| AGENTS/스킬·Codex 설정·로컬 검사기·로그 보존 변경 | [하네스 자체 경계](references/harness.md) |

프로젝트 시작에는 [보안 설계 양식](assets/security-profile.md)을 실제 프로젝트에 작성한다.
[보안 설계와 범위별 판정](../../../tools/harness/docs/project-workflows.md#동시-작업의-미결-범위와-완료-판정)에 따라 문서 해시·자원·경계·항목별 판단과 검사를 연결한다. 검토 중인 항목은 pending과 영향 경로로 남겨 다른 세션의 독립 구현을 막지 않는다. 관련 미결이 있으면 해당 범위의 완료와 전체 완료를 보류한다. 해시·필드 검사는 내용의 올바름을 대신하지 않는다.
재현과 수정은 [발견 사항 양식](assets/finding.md), 테스트 선택은 [검사 행렬](assets/test-matrix.md)을 사용한다.
양식은 작성되지 않은 상태를 통과로 표시하지 않는다. 관련 없는 항목은 근거와 함께 적용 제외로 남긴다.

## 실행 도구와 연결

로컬 사용법·종료 상태·지원 범위는 [보안 검사 도구](../../../tools/harness/docs/security.md)가 원본이다.
기본 검사는 오프라인이며 별도 네트워크 의존성 조회와 구분한다. 자동 설치·자동 업데이트·자동 수정은 하지 않는다.
프로젝트의 실제 권한/공격 사례는 workflow.toml의 checks로 등록하고 [verify-work](../verify-work/SKILL.md)에서 근거를 확인한다.
등록 검사에는 대상 코드·검사 범위·필수 환경을 연결한다. 테스트용 가짜 스캐너 통과를 실제 취약점 조회 성공으로 보고하지 않는다.

보안 검토는 외부 시스템 공격·원격 쓰기·운영 데이터 사용·노출된 자격 증명 시험의 권한을 새로 주지 않는다.
이미 승인된 범위의 로컬 격리 환경과 합성 데이터로 진행한다. 발견한 비밀값은 보고서에 복사하거나 유효성을 시험하지 않는다.
