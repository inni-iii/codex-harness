# 작업을 이어갈 수 있는 인수인계

여러 세션·다른 노트북에서 이어가거나 큰 단계가 끝났을 때 읽는다.
현재 작업의 notes.md에 [인수인계 템플릿](../assets/handoff.md)을 필요한 만큼 채운다.
짧게 끝나는 요청마다 별도 파일을 만들지 않는다.

## 남겨야 할 내용

- 목표·포함 범위·명시적 제약과 수용 기준의 현재 상태
- 관련 마일스톤·요구·갭과 계획 기준의 위치, 작업 전후 달라진 갭·근거·잔여/새 갭
- 현재 코드/문서 상태, 관련 경로, 필요한 실행 환경
- 확정 결정과 이유·근거, 사용자 미결정 사항
- 실제 검증 명령·cwd·대상 상태·결과·원본 위치
- 실패/탈락한 방법, 당시 조건, 다시 고려할 조건
- 남은 문제와 다음에 할 구체적인 한 행동

“테스트 통과” 대신 어떤 명령이 어떤 대상을 확인했는지 적는다.
개인 경로·자격 증명·전체 대화 복사본을 공유 기록에 넣지 않는다.
새 노트북에서도 필요한 자료를 레포에서 찾을 수 있게 상대경로로 연결한다.
로컬 .runtime 결과를 연결했다면 다른 노트북에는 없을 수 있음을 표시하고 재현 명령을 남긴다.
파일이 있다는 이유로 실제 결과를 검증했다고 하지 않는다.

## 작성 예시

```text
작업: 검색 결과 최신성 수정
목표: 느린 이전 응답이 최신 검색 결과를 덮지 않아야 함
읽을 자료: docs/projects/demo/brief.md, frontend/src/Search.svelte, 관련 행동 테스트
현재 상태: 취소와 오래된 응답 무시를 추가함. 브라우저 확인은 미실행.
확정 결정: 검색 API 계약 유지. 새 프레임워크 도입 없음.
검증: 실제 실행한 명령·cwd·소스 상태·결과 파일을 기록할 것.
실패한 방법: 타이머 해제만으로 이미 시작한 요청의 응답 경합은 막지 못함.
다음 행동: 해당 프로젝트의 브라우저 검사로 역순 응답과 화면 이탈을 확인.
```

예시는 기록 형식을 보여 주며 지금 레포에 해당 앱이나 검증 결과가 있다는 뜻이 아니다.

## 이어받는 순서

현재 요청과 과거 원문을 확인하고, 인수인계에서 목표·결정·실패·다음 행동을 복원한다.
기록이 가리키는 실제 코드·계약·근거를 읽고 달라진 상태를 확인한다. [갭 재평가](project-lifecycle.md#작업-시작-때-갭을-다시-재기)에 따라 관련 계획과 현재 상태를 비교하고 다음 작업을 고른다.
필요한 환경·명령을 사용할 수 있는지 확인하고 관련 수용 기준부터 이어간다.
과거 실패를 무조건 영구 금지하지 않는다. 조건이 바뀌었다면 그 차이를 근거로 다시 판단한다.
이전 검증이 현재 상태에도 유효한지 판단하고 유효한 결과만 재사용한다.

인수인계는 /compact hook이나 자동 세션 제어 기능이 아니다.
이 문서를 추가했다고 모델의 컨텍스트 보존이나 자동 재개가 보장되는 것은 아니다.
