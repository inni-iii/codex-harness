# 의도·경계에서 구현 가능한 설계로

새 행동·공유 API/데이터·권한·중요 품질 경계를 바꾸기 전에 읽는다. 사람이 정한 목표/마일스톤에서 요구·개념·대안·책임 경계를 확인하고, 구현할 O와 검증을 정한다. UI 디자인 값은 design-first가 맡는다.

## 분석 → 설계 → 정렬

1. 현재 요청·관련 Charter/요구·용어·기존 코드에서 확정 결정·가정·미결정을 구분한다. 인덱스와 개념 중심 검색으로 관련 정본만 읽는다.
2. 분석에서는 무엇을/왜·기존/새 개념·소유/수명·불변식·대안/탈락 이유·관련 위험을 정한다. 아직 필요한 결정을 임의 구현으로 확정하지 않는다.
3. 설계에서는 REASONS의 Requirements, Entities, Approach, Structure, Operations, Norms, Safeguards를 검토한다. 실제 계약의 입력/출력·책임·오류/복구·변경 위치·검증 가능한 경계를 연결한다.
4. 작업은 사용자 결과 단위로 분해하고 R ID·O ID·선행 O·허용 경로·확인 방법을 연결한다. 내부 메서드 전체를 코드처럼 반복 명세하거나 불필요한 계층을 만들지 않는다.
5. 정렬에서는 선택한 O와 task 수용 기준·현재 요청/기존 결정·범위·선행 근거·막는 미결정을 대조한다. 실제 근거와 설계 내용 SHA에 묶어 기록한다.

기존 요청/결정으로 충분하면 새 승인 질문 없이 진행한다. 선택에 따라 결과가 바뀌는 미결정만 묻고 그 경로는 답변을 기다린다. 다른 O에만 영향을 미치는 미결정은 독립된 현재 O의 시작을 막지 않는다.

## 문서와 근거

설계는 프로젝트의 기존 정본 또는 [양식](../assets/reasons-canvas.md)을 사용한다. 작으면 brief의 설계 문서로 관리해도 된다. 현재 구현이 아닌 계획/미결정은 구분하고, N/S는 관련 규칙·보안 정본 링크와 작업별 추가 제약을 적는다.

실행기는 Markdown의 첫 JSON fence에서 version/kind/profile·R/O·경로·의존·결정을 검사한다.7관점 본문과 metadata는 한 파일이다. 준비된 설계 artifact를 `design`, 현재 task/설계 SHA·선택 O·수용조건·결정 근거를 묶은 검토 artifact를 `alignment`로 연결한다. 상세 형식·CLI는 [설계와 구현 진입](../../../../tools/harness/docs/reasons.md)을 따른다.

행동/구조 변경은7관점의 실제 내용을 정리한다. editorial/exploratory는 Requirements/Operations/Safeguards를 유지하고 영향 없는 다른 관점은 not_applicable의 구체적인 이유로 짧게 처리할 수 있다. 분류를 빌려 행동/권한 변경의 설계를 생략하지 않는다. 관련 기존 계약은 references에 경로/실제 SHA를 묶어 재사용한다.

검토 결과를 ready로 쓰려면 선택 O의 미결정이 해결되고 선행 입력이 준비돼야 한다. 검사 계획은 실행 결과가 아니다. 형식 검사 통과·파일 존재·AI confidence를 의미적 합의나 사용자 응답으로 바꾸지 않는다.

## 보완할 위치

- 요구/관측 동작/권한/고정 경계 변경: 결정 근거와 관련 설계를 먼저 갱신하고 정렬을 다시 확인한다.
- 명세는 맞고 구현만 위반: 요구를 낮추지 않고 재현·좁은 수정·회귀로 연결한다.
- 동작 보존 구현 정리: 관련 회귀를 확인하고 E/Structure/O의 구현 설명을 최신화한다.

설계가 바뀌면 옛 alignment는 재사용하지 않는다. 활성 flow의 입력을 바꿔 통과시키지 말고 변경된 계약/근거에서 명시적으로 재시작한다. 이전 근거는 스냅샷/이력으로 보존한다. 문서 갱신·정본 연결·인덱스는 [명세 유지](../../docs-maintenance/references/specifications.md)가 맡는다.

배경은 [SPDD 조사](../../../../tools/harness/docs/spdd-reasons-research.md), 원문은 [REASONS](https://martinfowler.com/articles/structured-prompt-driven/)다. 원본의 Java 예제·고정 파일명·전체 읽기·자동 commit·매 단계 확인 규칙은 이식하지 않았다.
