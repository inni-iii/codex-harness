# 의미 있는 작업 단위와 검증 시점

## 작업을 너무 좁게 쪼개지 않기

기능은 사용자가 한 목적을 달성하는 흐름이다. 예: 게시물 작성 → 저장 → 목록/상세에서 결과 확인.
화면·API·저장·관련 오류 복구를 묶는다. 버튼·컴포넌트·파일·내부 함수 하나씩을 E2E 완료 단위로 잡지 않는다.
이번 요청의 수용 기준으로 경계를 정하고, 전체 서비스를 끝낼 때까지 확인을 미루지도 않는다.
순수 계산·연구·문서 작업에는 해당 작업의 관측 가능한 결과를 단위로 삼는다.

## 작업 시작에 사용자에게 알리기

실질적인 작업을 시작할 때 다음을 짧게 알린다. 실행 허가를 다시 요청하는 단계가 아니다.

- 이번에 끝낼 의미 있는 작업 범위
- 빠른 검사·통합·E2E 중 어디까지 검증할지
- E2E 수행 여부와 시점, 수행하지 않으면 이유와 남은 확인

예: “게시물 작성부터 저장 후 재조회까지 한 묶음으로 구현할게. 중간에는 타입·관련 단위 검사를 하고, 흐름 완성 후 실제 API를 통과하는 관련 E2E까지 확인하겠어.”
연구/문서 예: “이번에는 지침과 링크·설정까지 확인할게. 서비스 동작은 바꾸지 않아 제품 E2E는 수행하지 않을게.”
탐색 중 인증·공유 계약 등 새 위험이 생겨 범위를 넓히거나 E2E를 추가하면 실행 전에 변경 이유를 알린다.

## 실행 경계

| checkpoint | 작업 경계 | 확인 |
|---|---|---|
| edit | 구현 중 작은 변경 | 관련 정적·단위 검사. 전체 E2E를 반복하지 않음 |
| feature | 의미 있는 사용자 기능/요청 묶음 완성 | 관련 통합·사용자 흐름 E2E |
| integration | 독립 작업을 합친 상태 | 양쪽 요구·공유 경계·관련 회귀와 핵심 E2E |
| final | 제출·출시 판단 | 누적 영향과 위험에 맞는 전체 검사 |

checkpoint는 작업 의미를 대신 판단하지 않는다. 에이전트가 요청과 현재 상태에서 경계를 정한다.
필수 연결이 아직 완성되지 않았으면 미완성으로 남긴다. 비용 때문에 검사를 미룬 것을 해당 기준 통과로 쓰지 않는다.
명백한 오류·보안 결함·수집 실패는 기능 완료까지 기다리지 말고 관련 검사로 일찍 확인한다.

보안 검토 미결이어도 구현 중 검사는 실행한다. 검사 통과와 보안 검토 완료를 따로 보고한다.
해당 범위의 미결은 기능/통합 완료 근거로 사용하지 않고, 독립 범위의 진행까지 잠그지 않는다.
단계별 CLI 상태와 --full의 전체 미결 처리는 [프로젝트 명세](../../../../tools/harness/docs/project-workflows.md)를 따른다.
동시 편집에는 [협업 지침](../../plan-project/references/collaboration.md)의 worktree·고정 사본·통합 절차를 사용한다.

## 비용과 근거

프로젝트 checks의 run_at으로 비싼 검사의 시점을 등록한다. 기본값은 모든 checkpoint이며, --full은 시점 조건보다 우선한다.
명시적인 공유 impacts도 필요한 검사를 앞당길 수 있다. 경로 추정만으로 최종 검증을 대체하지 않는다.
실행 명령·설정은 [검증 명세](../../../../tools/harness/docs/verification.md)를 따른다.
긴 로그는 파일에 남기고 요약을 먼저 읽는다. 실패하면 해당 원본·trace를 읽어 원인을 확인한다.
재검증은 실제 영향 범위에서 수행한다. 유효한 결과만 재사용하고 브라우저/DB 상태는 소스 일치만으로 캐시하지 않는다.
작업 인수인계에는 실제로 확인한 범위와 deferred_checks·미확인 수용 기준을 남긴다.

## 로컬 서비스 검증의 완료 기준

GitHub 연결이나 CI를 전제로 삼지 않는다. 로컬의 같은 실행 명령·고정 의존성·격리 데이터·브라우저 환경에서 검사한다.
프로젝트가 정해지면 실제 정적/타입·단위·API/DB 통합·서버 기동·핵심 사용자 흐름 검사를 요구와 연결한다.
공통 하네스 검사 통과만으로 그 서비스의 검증 체계가 완성됐다고 하지 않는다.
완료 판단은 수용 기준별 실제 결과·기존 기능 회귀·관련 보안/오류 경계·미실행 항목을 대조해 수행한다.
다른 세션의 진행 중 변경은 [협업 지침](../../plan-project/references/collaboration.md)에 따라 구분하고 필요한 통합 검증을 남긴다.
