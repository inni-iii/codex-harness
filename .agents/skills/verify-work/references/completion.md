# 작업 기록을 닫을 때

작업 기록을 사용하는 요청의 완료 시점에 읽는다. 작은 답변마다 새 기록을 만드는 지침은 아니다.
[완료 계약과 실제 명령](../../../../tools/harness/docs/completion.md)을 따른다.

1. 기준별 실제 결과와 미실행 항목을 먼저 정리한다. 선언된 검사 범위가 그 기준을 증명하는지 확인한다.
2. artifact/source/check/experiment 중 해당 유형으로 파일과 해시를 연결한다. 연구·설계·실험도 코드 테스트로 대체하지 않는다.
3. 기능 완성 시 미룬 E2E를 수행하고 종료 코드·실행 수·실패·skip·불안정성·대상 상태를 확인한다.
4. review-template의 기준마다 실제 근거 ID와 판단 이유를 적고 자체/독립 검토 여부를 사실대로 표시한다. review v2의 verification에는 종류별 검토 영역·확인한 결함/회귀·실제 검토 라운드를 적는다. 마지막 수정 뒤 새 결함이 없는 재검토까지 [반복 절차](follow-through.md)를 수행한다.
5. evidence verify/complete를 실행한다. needs_revision이면 원인을 고치거나 미확인으로 남긴다.

전체 등록 검사 통과, 기록의 무결성 통과, 의미상 요구 충족을 구분해 보고한다.
추가 사람 승인을 기본 단계로 만들지 않는다. 현재 권한 안에서 에이전트도 검토와 완료를 수행할 수 있다.
