# 한 요청 안에서 검토·보완·회귀까지 이어가기

사용자가 점검·수정·구현·보완을 요청하거나 실제 작업에서 요구/계약 위반을 확인했을 때 읽는다.
“다시 봐줘”라는 후속 요청을 완료 절차의 필수 단계로 만들지 않는다.
사용자가 읽기 전용·분석/계획만 요청했으면 구현을 임의로 수정하지 않는다. 그 범위의 발견·근거·회귀 시나리오를 보고하고
실제 수정/실행이 남았음을 구분한다. 명시적으로 파일 쓰기까지 금지한 요청에서는 기록도 대화 안에 남긴다.

## 시작과 검토 범위

1. 현재 요구·계약·기존 결정·영향 범위에서 확인할 항목을 먼저 정한다. 구현 설명을 정답지로 삼지 않는다.
2. 작업 종류별로 정상 결과·반례/실패·공유 경계·회귀/근거를 대조한다. 연구는 출처 조건/반증, 실험은 입력/측정/집계, 설계는 계약/품질/대안을 중심으로 본다.
3. 사용자에게 의미 있는 작업 묶음, 이번 검사 범위와 E2E 여부/시점을 알린다. 이후 재승인을 기본 단계로 추가하지 않는다.

## 발견한 뒤에는 같은 요청 안에서 처리

1. 실제 결함과 추측·환경 실패·타 세션 진행 중 변경을 구분한다. 확인 전에는 결함이나 해결 완료로 단정하지 않는다.
2. 확인한 결함에는 F1 같은 ID를 붙여 task.json의 findings 목록에 등록하고 증상·재현 입력·기대 결과·영향·근거를 notes.md에 즉시 남긴다.
   기록이 없다면 확인된 결함이 속하는 의미 있는 작업 하나를 만들고 묶어서 관리한다. 결함 하나마다 새 task를 만들지 않는다.
3. 코드 결함은 가능하면 수정 전에 회귀 테스트를 추가하고 실제 실패를 관측한다. 이미 수정했다면 승인된 로컬 격리 공간에서 이전 상태를 재현한다. 현재 작업 트리의 타 세션 변경을 되돌리지 않는다.
4. 원인을 좁혀 수정하고 같은 회귀와 영향받는 기존 검사를 실행한다. 통과를 위해 테스트/완료 기준을 낮추지 않는다.
5. 입력·환경·보고서 오류를 고친 경우에는 그것이 앱 동작 결함의 재현인 것처럼 기록하지 않는다.
6. 새 결함이 나오면 기록→재현→수정→관련 검사로 돌아간다. 변경되지 않은 유효한 검사까지 매번 다시 실행하지 않는다.
7. 마지막 수정 뒤에는 변경 부분뿐 아니라 요구·관련 실패 경로·공유 경계·누락된 소비자·완료 근거를 다시 대조한다.

## 회귀 근거는 선택 사항이 아님

- 확인한 코드 결함을 수정하면 자동 회귀 테스트와 실제 수정 전 실패·수정 후 통과를 남기는 것이 기본이다.
  기존 테스트를 보강해도 된다. 같은 원인 묶음은 함께 검사하고 매 결함에 전체 E2E를 실행하지 않는다.
- 회귀 파일을 만드는 것으로 끝내지 않는다. 프로젝트 검사 명령에 수집되는지 확인하고 실제 실행된 테스트 이름·결과를 연결한다.
- 연구·설계에서 잘못된 주장/가정/계약을 확인하면 반례 입력·기대 판정·교정된 결과가 있는 재사용 시나리오와 원문을 남긴다. 가짜 코드 테스트로 대체하지 않는다.
- 자동화가 불가능하면 이유, 수행한 수동 시나리오, 수정 전/후 관측을 남긴다. 환경이 없어 실행하지 못한 것은 수동 통과가 아니다.
- 필수 검증을 실행할 수 없거나 결함이 남으면 blocked/needs_revision과 다음 행동을 기록한다. 테스트 파일만 추가하고 해결 검증 완료로 닫지 않는다.
- 범위 밖/타 세션 결함은 증거와 후속 위치를 보존하고 소유 경계를 지킨다. 원래 요구를 범위 밖으로 옮겨 완료하지 않는다.
- 단순 문구/형식 수정이나 재현되지 않은 의심에 의미 없는 회귀를 만들지 않는다. 기존 검사만으로 충분하면 해당 근거를 재사용한다.

## 종료 기준과 반복 비용

종료하려면 작업별 검토 영역이 확인되거나 제외 이유가 있고, 확인한 범위 내 결함이 해결되거나 명시적인 후속 범위로 분류돼야 한다.
필수 검사·회귀 근거가 유효하고 마지막 수정 뒤의 재검토에서 새 결함이 없어야 한다.
처음부터 결함이 없으면 한 번의 충분한 검토로 끝낼 수 있다. 정해진 횟수의 중복 검사나 형식적인 여러 AI 합의를 강제하지 않는다.

전체 테스트는 공유 영향·불확실성·최종 제출 범위에 맞춰 선택하고 E2E는 의미 있는 기능 완성 시 관련 시나리오를 수행한다.
도구가 실패하면 같은 명령을 무한 반복하지 말고 원인·조건을 바꿔 확인한다. 새 근거 없는 반복, 실제 권한/환경 부족,
양립하지 않는 요구는 그 지점과 계속할 조건을 기록한다. 실제로 할 수 있는 독립 작업은 이어간다.
이 절차는 사용자 허락 없는 원격 변경·설치·유료 호출·다중 에이전트 실행 권한을 만들지 않는다.

## 기록을 닫기

[review v2와 회귀 증거](../../../../tools/harness/docs/review-rounds.md)에 따라 검토 영역·라운드·확인한 결함과 회귀를 review.json에 연결한다.
새 증거로 계약/증거 해시가 바뀌면 기존 발견 사항을 보존하면서 리뷰를 갱신한다. 과거 발견을 지워 빈 목록으로 만들지 않는다.
중간에 통과했던 보고서가 이후 수정으로 과거 상태가 되면 artifact로 보존하고, 현재 완료에는 새 check 근거를 연결한다.
이전 결함의 after도 최종 관련 검사로 갱신해 새 수정이 이전 결함을 다시 만들지 않았는지 확인한다.
필드가 비었거나 회귀 근거가 없으면 evidence complete가 거부한다. 사람의 추가 승인을 모든 완료의 전제 조건으로 만들지 않는다.

재사용 가치가 있는 실패 원인·예방 원칙은 [학습 기록](../../plan-project/references/learning.md)에 적용 조건·제외 조건을 남기고
프로젝트 workflow의 context.rules 또는 해당 공통 스킬의 조건에서 다시 찾을 수 있게 연결한다. 개인 전역 규칙으로 자동 승격하지 않는다.
