# 프로젝트 컨테이너 실행 계약 양식

실제 프로젝트에 복사해 필요한 항목을 채운다. 이 양식 자체는 승인·구현·검증 근거가 아니다.

## 요구와 대상

- 대상 repo/코드 경로, 현재 요청 범위(조사/설계/구성/진단), dev/test/prod와 완료할 실제 사용자 흐름
- 적용할 지침/기존 계약, 유지할 데이터/서비스와 이번 변경 금지 범위
- 호스트/실행 플랫폼·로컬 endpoint, 필요한 CPU/RAM/디스크/GPU와 미확인

## 서비스와 이미지

| 서비스 | 실제 프로세스/역할 | context/Dockerfile | 언어/이미지 버전·lock | 내부/공개 주소 | live/ready | 자원/종료 |
|---|---|---|---|---|---|---|

프론트 framework/runtime과 SSR/CSR/prerender 선택, Python entrypoint/worker·DB pool, 외부 의존성, 이미지 식별/업데이트 경로를 적는다. 필요 없는 서비스를 추가하지 않는다.

## 실행·권한·저장

- 실제 Compose 파일 조합/경로 기준·profile·project 이름/포트/volume 격리, 준비/migration 순서와 실패 시 동작
- network·proxy/TLS·origin/header/cookie 신뢰, DB/스토리지 접근 권한
- secret 이름/주입 방식/소유자만 기록하고 값은 쓰지 않음. build 제외와 로그 민감정보 처리
- 영속/임시/cache별 경로·권한·데이터 버전·초기화·백업/별도 복원과 보존 정책
- 실행·중단·재개·업데이트/rollback·소유 자원 정리 명령/cwd 및 허용 경계

## 검증과 결과

| 요구 | 정상/실패/복구/격리 사례 | 실제 명령/cwd | 결과·종료 코드·근거 | 남은 조건 |
|---|---|---|---|---|

정적/build/start/기능/E2E/복원을 구분한다. 미실행은 미확인으로 적고, 선택·미결정·다음 행동을 연결한다.
