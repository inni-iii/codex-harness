# 외부 API·모델 호출의 실패와 예산

외부 API, LLM, SSE/스트림, 유한 배치 처리를 구현·검토할 때 읽는다.
기존 자원 수명과 API 계약도 함께 확인한다. 특정 제공자·SDK·모델·요금표는 고정하지 않는다.

## 호출 경계

입력·출력·오류·timeout·취소를 업무 규칙과 구분한다.
단일 제공자로 충분한 작은 기능에 다중 제공자 계층을 의무로 만들지 않는다.
구조화 출력은 schema로 검증하고 거부·빈 응답·잘림·잘못된 형식을 구분한다.
schema에 맞는 응답이라는 것과 내용이 사실/요구에 맞는다는 것은 별도 검사다.
알 수 없는 사용량은 0으로 채우지 않고 미측정으로 남긴다.

## 재시도와 대체

| 확인 | 판단할 질문 |
|---|---|
| 실패 종류 | 일시적 연결/제한/서버 오류인가, 인증·입력·계약 실패인가 |
| 중복 처리 | 이전 요청이 이미 처리됐거나 과금됐을 가능성이 있는가 |
| 횟수 | SDK 내부와 바깥 helper의 재시도가 중첩되는가 |
| 시간 | 개별 timeout·대기·재시도를 포함한 전체 deadline이 있는가 |
| Retry-After | 헤더를 지원한다고 적었다면 실제 구현이 초/날짜 값을 처리하는가 |
| 대체 제공자/모델 | 의미·지원 기능·비용·데이터 전달 위치가 바뀌며 승인 범위에 맞는가 |

잘못된 자격·입력 실패를 같은 요청으로 무조건 재시도하지 않는다.
프로젝트와 제공자 공식 문서의 정책을 확인하고 backoff/jitter·횟수·deadline을 정한다.
모델 품질·사용자 지정 모델을 임의의 최저가 우선 정책으로 바꾸지 않는다.
fallback을 사용했다면 실제 제공자·모델·정책을 확인 가능한 범위에서 보고한다.

## 동시성·예산

처리 중 호출 수뿐 아니라 대기열의 최대 크기·대기 시간·취소·과부하 응답을 정한다.
동시 호출 제한은 분당 요청/토큰 제한과 다른 제어다.
작업을 모두 만든 뒤 semaphore만 걸면 대기 task가 무제한 쌓일 수 있다.
batch의 생산 완료·작업 완료·worker 종료를 구분하고 빈 입력·실패·취소를 검사한다.

비용 한도가 실제 요구라면 호출 전 예상 사용량/예약과 호출 후 관측 사용량을 구분한다.
현재 누적액이 한도 이하라는 확인만으로 다음 동시 호출의 예산 초과를 막을 수는 없다.
실패·재시도·부분 스트림의 사용량도 가능한 범위에서 기록하고 미확인 비용을 밝힌다.
권한 없이 유료 호출·추가 제공자·백그라운드 모델을 활성화하지 않는다.

## 스트리밍

첫 출력 전 실패와 이미 일부 출력한 뒤 실패를 구분한다.
전달한 출력을 다시 이어 붙이는 재시도/대체는 중복·다른 답 혼합을 일으킬 수 있다.
자동 재시작이 필요하면 재개 지점·중복 처리·사용자 표시 계약을 별도로 설계한다.
클라이언트 종료·deadline·서버 종료 때 upstream response·작업·연결·큐를 정리한다.
전송 코드만 보지 말고 프록시 버퍼링·클라이언트 파싱·종료 이벤트도 필요한 환경에서 확인한다.

검증 사례는 정상·영구 실패·일시 실패·deadline·동시 요청·빈 배치·부분 출력 후 실패·사용자 취소 중 해당 항목을 선택한다.
외부 상태가 바뀌는 통합 검사는 캐시 재사용을 기본으로 켜지 않는다.
