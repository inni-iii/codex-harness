# 화면·키보드·접근성 증거

변경 화면의 상태·뷰포트·시각 차이·키보드 동작을 확인할 때 읽는다.
승인된 프로젝트 디자인 기준과 실제 UI 계약을 확인하고 관련 상태만 고른다.

- 좁은/넓은 뷰포트, 긴 텍스트, 실제 지원 테마와 오류·빈 상태를 확인한다.
- 공통 token/primitive/layout이면 대표 사용처와 인접 화면도 확인한다.
- 키보드로 도달·동작·닫힘·focus 복원을 확인한다. screenshot만으로 상호작용을 증명하지 않는다.
- 비교 기준·viewport·상태·screenshot 위치를 남긴다. 승인 기준이 없으면 임의의 픽셀 일치를 주장하지 않는다.

단순 문구·정적 스타일은 실제 화면 확인과 관련 회귀 범위에 맞게 고른다. 이 참조를 읽었다는 이유만으로 전체 E2E를 실행하지 않는다.
폼·인증·API/저장 흐름도 바뀌면 [사용자 흐름](scenarios.md)의 실제 경계를 확인한다.
브라우저·앱·디자인 기준이 없어 확인하지 못한 범위는 미실행/미확인으로 남긴다.
