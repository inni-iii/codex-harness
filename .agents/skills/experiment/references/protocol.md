# 실험 프로토콜

비교를 시작하기 전에 판단 기준을 고정하고 실패까지 기록한다.

## 실행 전 기록

- 질문·가설: 무엇이 좋아질 것으로 예상하는가
- 기준선: 현재 동작·버전·설정. 실행하지 못했다면 그 이유
- 입력: 데이터 식별자·범위·전처리·평가/조정 분리
- 지표: 주 지표, 반드시 유지할 품질 하한, 시간·비용·자원 측정 단위
- 실행 조건: 코드 상태, 의존성 잠금, OS·하드웨어, 모델/도구 ID, 시드·동시성·캐시·워밍업
- 예산·중단: 호출·시간·비용 한도, 실패 시 중단 조건
- 결과 위치: 설정, 원본 출력, 요약, 실패 장부

## 단계별 실행

작은 입력으로 실행기·평가기·실패 기록이 작동하는지 먼저 확인한다.
기준선과 후보의 데이터·평가법을 맞춘다. 한 조건을 바꾸거나 함께 바뀐 조건을 분명히 적는다.
속도 측정에서는 준비·다운로드·워밍업·실제 처리 시간을 분리한다.
비결정적 작업은 변동을 측정할 필요가 있을 때 반복하고, 성공한 시도만 골라 비교하지 않는다.

| 항목 | 기록 예 |
|---|---|
| 정상 종료 | 관측값·단위·원본 위치 |
| 실행 실패 | 종료 코드·실패 단계·시간·발생 비용 |
| 시간 초과 | 제한 시간·중단 상태·회수된 결과 범위 |
| 평가 불가 | 누락 이유·전체 분모 포함 여부 |
| 제외 | 사전 기준인지·새 사유인지·결론 영향 |

## 해석

평균만으로 꼬리 지연·특정 집단 실패를 가리지 않는다. 해당 요구에 맞는 분포·실패율도 본다.
작은 표본·다른 하드웨어·다른 입력에서의 결과를 전체 환경으로 일반화하지 않는다.
미측정 비용은 0으로 채우지 않는다. 실제 지출, 단가를 적용한 추산, 향후 운영 가정을 분리한다.
채택·기각·보류와 각각의 조건, 다음 실험에서 바꿀 변수를 남긴다.

반복 실행은 불안정성 확인이나 조건 변경에 근거해 선택한다. 같은 결정적 검사를 근거 없이 반복하지 않는다.
